## Web UI：发送等待反馈 + 右侧栏展开动画（packages/coding-agent）

- 发送后 AI 侧留白根因：`transcript.js` 只在 `snap.active` 时传 `live`，而 pending 阶段 `snap.active=false`，
  于是 `turnOutcome` 里既有的 `pending → "running"` 分支从未被使用。修复：在 turns 映射里加 `awaiting`
  （`!live && isLast && !turn.final && !turn.steps?.length && turn.user?.pending`），复用现有 `ProcessSummary` 工作行，
  未新增任何 UI/状态。实测工作行 60–71ms 出现，首字到达后无缝替换，失败/停止后消失。
- 右侧栏“撞出来”根因：`.panel` 自身带 `translateX(28px)+opacity` 过渡，与轨道宽度过渡叠加成两条不同曲线。
  修复：`.panel-slot` 改为 `justify-content:flex-end` + `overflow:hidden` + 槽位淡入，阴影移到槽位；
  `.panel` 去掉位移/透明度过渡。实测展开全程 `panelLeft` 恒定（内容零位移），轨道 0→566px 约 280ms。
- 首字延迟实测（mock provider 首包 400ms）：点击→气泡 60–71ms，`/api/prompt` 44–72ms，`run_state starting` 72–75ms，
  `agent_start` 77–80ms，首个 `message_start` +85ms，服务端向 Provider 发出请求在 +823ms（≈740ms 在 agent 启动/
  系统提示/首轮请求准备），首 token 1226–1310ms。未改服务端（无证据大改被规格禁止）。
- 验证：`web-optimistic-send-browser.test.ts` 扩为 send/reject/late 三场景（late = 200 后广播 `prompt_rejected`，
  模拟 Provider 失败），断言“立即有 `.summary.live`、稳定后消失、草稿恢复、无重复”；首次交互前加一次不计时预热，
  否则测到的是浏览器首帧/JIT 成本（95ms vs 稳态 3–5ms）。

  干净代码上同样失败）、`web-experience-polish-browser.test.ts`（test.js:57 选择器 undefined）、
  tsgo 3 处报错（`packages/ai/test/openai-responses-tool-schema-normalization.test.ts`、

## Workspace 侧栏卡顿（新建→删除→立刻选文件夹 约 1 分钟无响应）

- 根因（实测，非推测）：`deleteWorkspaceArtifacts()` 结尾无条件 `refreshArtifactIndexes(dataRoot)`；真实数据根
  （1445 工作区 / 227007 产物 / 全局 index.json 128MiB）一次同步全量刷新 **52.3s**，单线程 HTTP 服务被完全冻结，
  于是“删除”和随后的 `/api/fs/pick-folder` 都在队列里等着。新建的工作区没有任何产物也会走这条路径。
- 修复：`deleteWorkspaceArtifacts` 只删本工作区会话产物目录，按条目摘除两个索引（全局 + 本工作区），
  无产物时 0 次索引写入；索引不可解析时回退 `refreshArtifactIndexes`（保留原一致性兜底）。
  实测：无产物 0–1ms；合成 120 工作区/3600 产物 608ms → 127ms；真实数据根“有产物”路径仍要约 1.5s
  （128MiB 读 466 + parse 330 + stringify 693ms，无法避免全文件重写），已如实记录为已知残留。
- `/api/sessions/archived` 原实现一次不间断遍历全部会话（3.8–4.6s），把无关请求最长挡 3.7s；
  改为 `ARCHIVED_SCAN_SLICE = 50` + `setImmediate` 分片后最长等待约 2.1s（剩余是 `SessionManager.listAll` 自身
  ~1.9s 不可中断块，未改动）。
- 前端：`removeWorkspace` 改为乐观删除（行立刻离场、失败回滚、按具体 mode 刷新）；`loadWorkspaces` 加
  in-flight 合并（`workspaceLoads` map + `again`），避免 action 与 `workspaces_changed` 事件并发触发多轮
  3.6–6s 的 unbound 扫描。动画/文案/布局/业务语义未改。
- 测试：`session-artifacts.test.ts` 新增 3 例（只摘本工作区条目 / 无产物不写索引 / 全局索引漂移时仍清理本工作区索引）；
  `web-frontend-logic.test.ts` 新增 removeWorkspace 乐观删除 2 例（需 stub `document.documentElement` + `matchMedia`，
  并用 fake timers 挡住 `savePrefs` 的 300ms 共享偏好定时器）。
- 既有失败（用 `git stash` 在 HEAD 上复核，同样 4 条）：`web-host.test.ts` 的 isolated modes / deferred drafts ×2 /
  provider detect。`biome check routes-sessions.ts` 的 3 处（unused `dirname`、organizeImports、`??=` 赋值表达式）
  也是既有问题。浏览器用例在本机被 skip（无 Chrome），Electron/真实桌面端未验证。
