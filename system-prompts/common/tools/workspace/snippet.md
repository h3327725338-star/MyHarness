# Tool description
- Control the desktop workspace: list, open (also in the background), close, activate, reorder and restore the file, media and browser tabs of the right-hand panel; drive any number of browser tabs side by side by `tabId`, on screen or not: navigate, read (text, DOM, accessibility tree, interactive elements with their centre points), find, run page scripts, upload a workspace file, save a link as a file (`download`) and read downloads and requests. A tab on screen has the size of the user's panel; a background tab is at least 1280×800. A click that starts a download waits for it and returns the saved file's path. Use your own mouse and keyboard: `screenshot` shows the tab in the page's CSS pixels, `mouse` clicks, double-clicks, right-clicks, hovers, drags or scrolls at an x/y point of that picture (images and canvases included), `key` presses keys or combinations, `type` types into the focused element. Point at elements the way a person does: `click`, `type`, `mouse` and `scroll` also take `label` (the element's visible words, placeholder or accessible name), `selector` or `index`, scroll it into view and use the real mouse; `type` replaces a field's text, picks a <select> option and can press Enter; a navigation a click starts is followed. `wait` waits for a selector, text or label to appear or disappear, or for the page to settle. Save round trips: `screenshot: true` on an action returns the picture after it, and `batch` runs several steps in one call with one screenshot at the end. Bookmarked sites are trusted by the user: open them with `bookmark`, sign in with `login` (the app fills the saved login; you never see the password), and their permission requests are allowed automatically; `answer_permission` allows or denies a pending request of any site. Play, pause, seek and set volume on media tabs. Every call reports the state that was reached, and the tool exists only in the desktop app.
