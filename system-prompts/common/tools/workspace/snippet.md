# Tool description
- Control the desktop workspace: list, open, close, activate, reorder and restore the file, media and browser tabs of the right-hand panel; drive any number of browser tabs side by side by `tabId`, on screen or not: navigate, read (text, DOM, accessibility tree, interactive elements with their centre points), find, run page scripts, upload a workspace file, save a link as a file (`download`) and read downloads and requests. Website tabs you open start in the background and muted, so the user keeps their view; an action on a page the user is looking at runs in a background copy of it (same address and sign-in) unless the user asked you to act on their page (`onUserTab`). Read whole pages instead of paging by hand: `read` (with `scroll` for feeds and lazy lists, `links`, `tables`), `collect` for a paged list, `read_many` for several addresses at once. A tab on screen has the size of the user's panel; a background tab is at least 1280×800. A click that starts a download waits for it and returns the saved file's path. Use your own mouse and keyboard: `screenshot` shows the tab in the page's CSS pixels, `mouse` clicks, double-clicks, right-clicks, hovers, drags or scrolls at an x/y point of that picture (images and canvases included), `key` presses keys or combinations, `type` types into the focused element. Point at elements the way a person does: `click`, `type`, `mouse` and `scroll` also take `label` (the element's visible words, placeholder or accessible name), `selector` or `index`, scroll it into view and use the real mouse; `type` replaces a field's text, picks a <select> option and can press Enter; a navigation a click starts is followed. `wait` waits for a selector, text or label to appear or disappear, or for the page to settle. Save round trips: `screenshot: true` on an action returns the picture after it, and `batch` runs several steps in one call with one screenshot at the end. Bookmarked sites are trusted by the user and each says what it is for (the list arrives in the conversation as a bookmarks reminder; `bookmarks` with `query` searches it): when a request concerns what a bookmark is for, use that site on your own initiative without asking which one: open it with `bookmark`, sign in with `login` (the app fills the saved login; you never see the password), and its permission requests are allowed automatically; while you work, `bookmark_note` quietly fills in or improves a bookmark's note from what the user really does there (never a note the user wrote); `answer_permission` allows or denies a pending request of any site. When a page needs a sign-in you cannot do with `login`, or a human check (CAPTCHA, bot check), never skip the page or work around it: `handoff` puts that tab in front of the user with your request and waits until they are done, then you continue. Play, pause, seek and set volume on media tabs. Every call reports the state that was reached (`open` says `on_screen=yes` only when the user can see the tab; `on_screen=no` means this chat is not on the user's screen, so do not say it is open in front of them), and the tool exists only in the desktop app.
