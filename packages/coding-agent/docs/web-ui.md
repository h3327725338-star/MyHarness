# Web UI

MyHarness 使用统一的 Web UI，可由本机浏览器或独立 Electron Windows 桌面宿主打开；桌面开发、打包、数据锚点与限制见 [Desktop README](../../desktop/README.md)。右侧详情面板是一个统一的多标签工作区：原有四个面板（Changes / Files / Terminal / Session）各占一个标签，还能同时打开任意多个本地文件和网站；Electron 下每个网站标签由主进程的一个 `WebContentsView` 承载（真实 Chromium 文档，不使用 iframe/webview），并共用一个持久化的第三方分区保存 Cookie 与登录态。它使用现有 `AgentSessionRuntime` / `AgentSession`、Session、Settings、Provider、Tool、Git checkpoint 和 Extension，没有第二套 Agent 逻辑。终端 CLI/TUI 已移出本仓库；Web Terminal 面板仍保留。

## Coding / General 双模式

接口约定见 [chat-modes-backend.md](chat-modes-backend.md)。原 `POST /api/prompt` 的 `mode` 是消息投递策略，与产品模式不同。浏览器接入：

- 侧栏左上角椭圆开关（`web/js/mode-switch.js`）：左 Coding、右 General，两侧颜色各自跟随对应模式保存的配色（深色：经典炭黑为蓝色、静谧森林为苔绿、暖夜琥珀为琥珀色；浅色共用基础蓝色），两色常显；当前模式修改主题、切换模式及刷新首屏都会同步两侧颜色，任务标记也沿用各自颜色；滑块切换时拉伸、挤压并轻微回弹，内部代码／聊天 SVG 图标连续变形，颜色随模式平滑过渡。关闭动效时直接到达最终状态。切换调用 `POST /api/modes/open`，先保存草稿和当前聊天；开关先立即响应点击意图；已加载的最近聊天直接切换，不等待草稿保存响应或列表刷新；展开从不等待目标模式的 Workspace / 聊天列表：已加载的列表立即显示并在展开的同时刷新；从未加载的列表在展开时显示 “Loading…”，读到后再淡入；工作区为空时侧栏不显示任何占位行，“Default”分组直接紧贴“Workspaces”标题下方。首屏准备完成后立即在后台读取另一模式的列表（只读列表，不打开、不新建、不保存任何聊天，页面在后台时跳过），所以通常第一次点击时列表已就绪。首次打开未加载聊天时先切到目标模式的占位页面，服务端准备和数据读取在后台完成；失败时保留目标页面、模式开关与侧栏选中，正文提供错误说明和重试，不自动退回原聊天。新页面由 View Transition 从开关中心用 600ms、无模糊的圆形边界扩开；动画中再次点击可从当前进度反向播放，收回后恢复原聊天。浏览器过渡快照排除原开关的鼠标命中时，捕获开关实际区域内的 pointerdown 并转交原按钮；不截获区域外点击（`web/js/mode-transition.js`），浏览器不支持或关闭动效时直接切换。设置 → 外观 → 配色主题按当前聊天模式分别保存浏览器偏好 `colorThemes.coding` / `colorThemes.general`（`classic` / `forest` / `amber`，未设置或无效值默认 `classic`），通过 `<html data-color-theme>` 覆盖 `tokens.css` 的颜色变量；修改只影响当前模式，切换模式恢复各自的选择。旧共享 `colorTheme` 兼容读取为两边初始值，不丢失已有选择。经典炭黑沿用原 Coding 灰黑与蓝色；静谧森林恢复已确认的克制灰绿方案（侧栏 `#1f2221`、主区域 `#292e2b`、浮层 `#363c38`、苔绿强调色 `#a7c080`）；暖夜琥珀沿用暖棕方案（深色采用克制的暖棕深灰配色：外围和侧栏 `#23201e`、主聊天区 `#302b28`、输入框和浮层 `#3e3732`，以轻微棕调的深灰按明暗逐级抬升；正文使用中性柔白，次要文字和边框使用低饱和暖灰，柔和琥珀强调色 `#d4ae82` 主要用于按钮与选中标记；消息气泡轻微偏棕，代码块保持暖深灰，Diff 使用独立的绿／红状态色；布局和交互不变，浅色显示共用原 Coding 浅色基础配色，三套主题目前仅改变深色配色）。三套配色的深浅显示按同一套对比度标准检查（`test/web-mode-theme.test.ts`）：次要文字 `--text-3` 不低于 4.5:1，更淡的 `--text-4` 不低于 3:1，状态色（ok / warn / danger）在各自淡底上不低于 4:1，控件边框 `--border-strong` 看得见；General 深色状态色使用可读的柔和绿、暖黄和浅红，实心危险按钮的字用 `--on-danger`（深色）而不是白色。开关有独立的 View Transition 名称，页面展开时仍显示自身动效。
- 当前界面模式只保存在浏览器偏好 `chatMode`，并始终等于屏幕上聊天的模式：从通知或任务列表打开另一模式的聊天时，界面随之切换。页面初始化读 `GET /api/modes/state`，必要时用 `/api/modes/open` 恢复该模式最近的聊天；服务重启恢复时保留原聊天。
- 两边各有 Workspace / 聊天列表、展开状态（Coding 用原 `expanded`，General 用 `expandedGeneral`）和列表缓存；列表、新建、Workspace 添加/移除/重命名请求都带 `mode`。slot 列表按 `mode` 过滤后用于侧栏状态。
- 开关两侧各显示该模式任务：运行中为呼吸点；待处理、失败、部分完成、完成、取消用不同图标。另一模式有待处理或未读结果时，开关下方显示一行简短汇总（只有一个时直接写聊天名；开头的模式标签与开关滑块用同一对颜色：模式色实底、`--mode-on` 文字），点开是任务列表，点任务直接打开对应 slot 并把它存为该模式最近聊天。状态全部来自 `/api/slots` 与 `slots` 事件；未读仍只由屏幕上（同模式）聊天通过 `/api/seen` 清除。
- 草稿：编辑后约 0.7 秒保存到 `POST /api/modes/state`（发给该聊天的 slot，以 Session ID 为键），切换聊天/模式前和页面隐藏时立即发送；发送成功后清除。图片附件保存为 `{ kind: "image", name, mimeType, data }`，已上传文件保存为 `{ kind: "file", name, path }`，恢复时还原为 Composer 原有格式。本标签页内存中的草稿优先于服务端记录。
- 普通聊天选择会保存为该模式最近聊天；为避免留下空文件，没有内容的空白聊天只在离开该模式时才保存。已保存但没有消息的聊天在侧栏显示为“New chat”（和还没保存的新聊天一样，没有时间和菜单）；它不再是屏幕上的聊天之后，只要没有置顶或命名、没有草稿、也没有在已打开的会话里有内容，就不再列在侧栏（带着离开动画收起，不再是“空聊天一直留在列表里”）。文件不会被删除；它再次成为该模式的最近聊天时，又会作为当前聊天出现。是否“空白”由服务端判断：聊天列表接口（`/api/workspaces/sessions`、`/api/sessions/unbound`、`/api/sessions/archived`）给每个聊天返回 `blank`，只有 JSONL 里除了创建时写入的模型和思考级别设置之外没有别的记录（没有消息、名称、标签、操作卡片等）时才为 `true`；侧栏据此并结合本页已知的草稿和已打开的会话决定是否列出（`chat-order.js` 的 `isLeftBlank`），归档区不过滤。“输入过”由输入框当前内容决定：有文字或附件时页面发送 `POST /api/sessions/touched`（`{ touched: true }`），删空（只剩空白也算空）后发送 `{ touched: false }`，同一个聊天的这些请求按顺序一个接一个发出，不会让较早的请求后到；草稿保存 `POST /api/modes/state` 也按草稿内容更新同一个标记。所以输入过又删空的新聊天和没输入过的一样是空白聊天，离开后不再列在侧栏。
- 设置 → 个性化（Personalization）：纵向平铺“Coding 模式全局个性提示词”与“General 模式全局个性提示词”两张默认折叠的卡片（Collapse 高度+透明度平滑展开），无字数上限、不再显示字符计数；面板底部单个“保存”一次 POST 同时持久化两项，收到 `mode_preferences_changed` 时重新读取（有未保存修改时不覆盖）。两套提示词只注入各自模式，优先级最高（见 chat-modes-backend.md）。卡片内层不再重复包一层通用卡片体，说明文字与输入框直接由 `.personal-body` 承载，卡片边框到输入框的单侧留白收紧到 13px（1px 边框 + 12px 内边距）。每个输入框右上角（距边框 6px）有一个全屏编辑按钮（`maximize` 图标，悬停提示“全屏编辑”）：点击平滑展开为大编辑视窗（`min(1100px, 100vw − 48px)` × `min(820px, 100vh − 64px)`，叠层 z-index 220，高于设置弹窗与引用卡片、低于菜单与图片灯箱），标题沿用卡片标题，右上角收起按钮（`minimize` 图标）；打开时大框自动聚焦并继承原框的光标/选区，收起后焦点回到该放大按钮，Tab 只在收起按钮与大框之间循环，点击遮罩空白同样收起。按 Esc 只退出全屏视窗、不关闭设置弹窗（再次 Esc 才关弹窗）；中文输入法组合期间的 Esc 不触发退出，不打断拼音。大框与小框共用同一份受控内容，因此两边实时双向同步；撤销历史按元素各自独立、两个输入框之间不互通（浏览器原生行为）。保存语义不变：仍在退出全屏后点面板底部的“保存”。
- General 工作区（不含 General 组）`...` 菜单：“工作区设置”弹窗分两组（名称与工作区指令；启用工作区记忆与允许工作区资料库），指令框右上角复用同一个全屏编辑（`PersonalFullscreen`，Esc 只退出全屏，仍由弹窗底部“保存”提交），弹窗内不再列资料或上传。相邻的“项目资料”打开资料页（`web/js/sources-page.js`）：覆盖在会话区之上，下面的聊天保持挂载（滚动位置、运行中的任务、草稿都不变），左上角返回回到原聊天；切换聊天或切到 Coding 模式时自动关闭。页头和空状态都有“添加文件”和“添加文件夹”（两个独立的隐藏文件选择框，后者带 `webkitdirectory`；浏览器拿不到空目录）。资料数量不设上限，单文件上限 500 MiB；开始前逐个检查，只要有文件超限或读不出，整批都不上传，并逐条列出是哪个文件、属于哪个文件夹、什么问题；压缩包、`.git`、`node_modules`、`.DS_Store` 等都照常上传。上传分片进行（每片 4 MiB，`POST /api/workspaces/sources/stage` 先整批检查并准备，`/chunk` 逐片写入，`/finish` 完成一份资料），4 个文件同时传，显示“正在上传 x / y”；中途出错立即停下整批，提示已成功传完多少个，已完成的保留在列表里，点“继续”只补传剩下的（只在当前页面有效，刷新后要重新选择）。一个文件夹在列表里只占一行（文件夹图标、名称、文件数、总大小、时间），点击用统一的 `Collapse` 动效逐层展开子文件夹（`GET /api/workspaces/sources/tree`）。排序开关可选“最近修改”或“文件类型”（文件夹在前、再按扩展名），展开的子项用同一规则，选择记在本浏览器。单个文件、子文件夹和整个文件夹都能删除，均走确认弹窗（`POST /api/workspaces/sources/delete`，删除子项时带 `path`）。关闭“允许工作区资料库”只停止向对话注入资料清单，资料页照常列出和删除。侧栏聊天行不再有附件按钮与展开区；消息里的附件卡片和输入框附件不变。

## 对话自动命名

设置 → 智能体 → 助手提供“对话自动命名”行，复用现有模型、思考级别和开关控件；默认关闭，启用后跟随主模型，也可以选择独立命名模型。第一条完整回复后后台生成标题，不受十分钟冷却限制；已有自动标题后，有新增完整回复且距上次成功检查至少十分钟时，在任务、收尾和 Git 操作均空闲后检查，主题未明显变化则保留标题。请求期间出现新回复时先采用有效结果，再在空闲时立即补查最新内容。只执行过 `/commit`、还没有任何完整回复的 Chat 也会命名：用这次提交的说明文字生成标题，推送、撤销、恢复和失败提交的记录不算素材；已有完整回复的 Chat 仍按对话内容命名，之后的提交不会额外触发改名。手动标题和显式 AI 重命名不会被自动覆盖，原菜单入口不变。

后台命名不纳入 Chat active/completion、通知或服务退出保护。检查进度保存为 Session custom entry；关闭/释放 runtime 时取消请求和定时器，下次加载对应 Chat 时补查，不遍历未打开的历史 Chat。失败（包括模型不可用、空输出）保留原名和待检查内容，首次失败后每隔五秒再重试，最多三次，仍失败则停止。侧栏对应 Chat 旁不再插入行内文字或星星图标：命名进行中或重试时，只在该 Chat 行最左侧的状态槽里显示一个柔和呼吸的微光小点（任务同时运行时小点嵌在旋转圆环中心，共用同一槽位，右侧时间照常显示），“命名中/命名重试 n/3/命名失败”和失败原因只在该小点上悬停或键盘聚焦时通过原生 title 提示查看；失败时小点换成一个同样式的普通图标按钮，点击可重新尝试（`POST /api/sessions/naming-retry`，传 `{ path }`，要求 Chat 已打开），不用橙色文字或警告色强调；任务运行中该重试按钮暂让位给旋转圆环（命名本来也要等空闲才处理），运行结束后恢复显示；命名完成后小点平滑淡出，标题就地更新。`SlotStatus.conversationNaming` 随 `conversation_naming` 事件触发的 slots 更新广播，也随 `GET /api/slots` 恢复；成功后清除标记，不挤占任务/未读状态。失败进度持久化，重新加载不会无限重试同一条回复。配置和持久化字段详见 [Settings](settings.md#conversationnaming对话自动命名)。

## 会话治理、快捷键与指标

- 归档和删除同时识别已保存的 Chat 与仍在服务内存中的 Chat（例如输入过草稿或导入附件、尚未发送的对话）。归档未保存的 Chat 时先保存现有会话记录，不生成虚构消息、不把未发送草稿加入模型上下文；归档后可从磁盘恢复会话，未发送草稿仍只按现有浏览器规则保留。删除未保存的 Chat 时释放其 slot，沿用附件清理与产出保留选项；删除当前 Chat 保持请求所在 slot 并替换为新 Chat。任意未知路径仍拒绝操作。
- 会话三点菜单支持归档/取消归档。归档是独立的侧栏逻辑文件夹：在 JSONL 旁保存 `.archived` 标记，保留原磁盘路径、Workspace 归属和分支引用，不搬动原数据目录。归档只在列表里就地移动：被操作的那一行收起并淡出，进入侧栏底部的“已归档对话”文件夹（取消归档则回到原分组）；该文件夹只在存在已归档对话时出现，没有归档对话时不占侧栏空间（归档是“从分组隐藏 + 可恢复入口”，不是删除），页面不刷新、不重新载入对话；正在显示的 Chat 归档后继续留在屏幕上（不再替换成新 Chat），正在运行的 Chat 拒绝归档。服务端拒绝时列表恢复原状。
- 会话三点菜单支持置顶/取消置顶（`POST /api/sessions/pin`，在 JSONL 旁保存 `.pinned` 标记，删除 Chat 时一并移除）。置顶的 Chat 行首有图钉，排在所属分组最前；归档文件夹里不按置顶排序。
- 每个分组内的排序：刚新建、还没发消息的空 Chat 在最前（不管它有没有写盘——只要它还是屏幕上正在用的那一个；已经写盘、但不在屏幕上的空会话按它自己的时间参与排序），然后是置顶的、正在运行的，其余按最近活动时间从新到旧（`web/js/chat-order.js`）。最近活动时间取保存的最后一条消息时间和服务端 slot 状态 `lastActivityAt`（任务开始/结束、`!` 命令、Git 操作时更新）中较新的一个；只是点开查看不算活动。发送消息、生成中、工具调用、提交的 Chat 立即排到分组第一行；行换位置时只有该行和被它越过的行用 transform 平滑滑动，列表初次出现时不逐行播放展开动画。一个分组默认列出 12 行，“再显示 n 个”一次列出其余的行：这些行直接出现，整组的高度用统一动效从原高度过渡（`ui.js` 的 `useHeightGlide`，最多过渡一屏的高度，更远的部分在屏幕以下，随最后一帧出现）。后台 Chat 的任务结束后也会重新读取它所在分组的列表。
- 点击侧栏里的 Chat 后该行和正文目标立即同步；未加载的 Chat 先显示带标题的占位页面，后台并行读取快照与消息，已加载的 Chat 复用原状态。连续快速点击以最后一次为准，旧请求返回不能覆盖新选择；失败保留目标与重试入口。加载期间可以编辑独立目标草稿，但只有真实 slot 的快照和消息都就绪后才允许发送；未知目标拒绝附件上传，所有 prompt 明确指定已确认 slot，绝不回退到原 Chat。首次获取资源的并发请求合并；改动卡 Diff 在悬停/聚焦时预取，分支浮层打开时后台预取 Worktree，缓存均按 Chat 隔离且有界。所有“下一帧再显示”的动效都带计时器兜底，页面被遮挡或不在前台时也不会让行一直不可见、不可点。Web 删除确认调用永久删除，默认保留对话产出及最小来源信息，删除聊天、附件和工具记录；确认框提供默认不勾选的“同时永久删除产出文件”。勾选后删除原文件并同步移除工作区/全局汇总引用，失败显示原因，不假装成功。
- 设置 → Keyboard shortcuts 录入浏览器专属快捷键，各行输入框统一为 120px 宽度，保存在浏览器偏好中；默认为 Ctrl+Alt+K/N/B/L/,/F（命令面板、新 Chat、侧栏、输入焦点、设置、筛选）。重复绑定与非 Ctrl+Alt+字符组合拒绝保存并标红；关于、侧栏和命令面板读取同一注册表。系统/浏览器扩展自定义的全局绑定不在页面可检测范围内。

## 消息索引条与引用跳转

对话区右缘（滚动条左侧）有一条细索引条（`web/js/message-rail.js`）：每条用户消息一根短刻度，位置按该消息在对话中的实际位置成比例分布（刻度间距至少 7px，索引条高度约每条 26px、至少 180px、最高占满对话区上下各留 44px，垂直居中，距右缘 12px，热区宽 40px），当前阅读的消息（视口顶部所在的那一轮，贴底时为最后一条）用强调色点亮。指针靠近时附近刻度按距离变宽，最近的一根变亮并在左侧弹出提示卡（序号 `n / 总数` + 该消息自己的第一行，不含引用块和附件列表）；单击平滑滚动到该消息（时长随距离 200–520ms，关闭动效时直接到位），按住拖动则按指针位置即时擦洗；聚焦后可用方向键、Home/End 逐条移动。只统计已挂载的轮次（更早的轮次随「显示更早消息」加入）；少于 2 条消息或聊天列过窄（`data-w="xs"`）时不显示。

已发送消息里的引用块（`>` 段落）可点击：`web/js/message-nav.js` 的 `jumpToQuote` 在该消息之前的对话文本里找最近一处相同原文（忽略空白差异；其他消息里的引用块不算原文；整段找不到时按开头约 80 字再找），滚动到视口约 30% 处并用 CSS Custom Highlight（`myharness-jump` 强 → `myharness-jump-fade` 淡，不支持时用 `.quote-hl` 临时包裹）闪一下原文；跳转后底部出现「返回」胶囊（占据“跳到最新”按钮的位置，二者不同时出现），点击回到原位置；手动滚回原位置附近、过约 8 秒或切换对话时自动消失。原文不在已加载范围内时提示一次，不滚动。索引条和引用跳转都通过 Transcript 注册的滚动控制器（`registerScroller`）滚动，会让“跟随底部”松手；用户滚轮、触摸、按键或按下鼠标立即中止正在进行的动画。浏览器回归见 `test/web-message-rail-browser.test.ts`。

## 本地文件入口

对话中的本地 Markdown 链接（绝对路径、`file:///`、相对路径）直接操作原文件；普通正文里的文件名、路径和行内代码，先排除 85 个代码/文本扩展名（如 `.ts` / `.md` / `.json` 等，`web/js/local-file-links.js:15` 的 `LOCAL_AUTOLINK_BLOCKLIST`，显式 `[text](path)` 不受影响），其余在确认存在后变为可点击入口。相对路径以所属 Chat 的工作目录解析。左键把文件作为右侧工作区的文件标签打开（已打开则切换过去，不覆盖其他标签；`web/js/local-files.js` 的 `openLocalFileInWorkspace`），按文件类型进入标签里已有的查看或编辑视图；文件夹没有面板视图，左键仍直接进入；右键显示紧凑的应用菜单：复制（子菜单含文件名和完整路径）、打开方式（子菜单含默认应用及当前系统注册的程序）和资源管理器定位／打开。悬停展开右侧子菜单，屏幕右侧空间不足时向左展开；支持方向键进入／退出子菜单、Esc 逐层关闭，以及点击外部关闭。菜单打开用 pop-in、关闭用 pop-out（110ms，`web/js/local-files.js:9`），连续右键只保留一个菜单。菜单沿用当前主题的背景和高亮，不堆叠图标或独立大按钮。文件打开方式通过 Windows Shell association 枚举和调用，文件夹从系统登记的目录命令发现；未向系统登记的程序不自动猜测，程序清单不写死。不存在的普通路径保持原文，显式链接操作失败会显示错误。

`POST /api/files/local` 提供 `resolve`、`choices`、`open`、`reveal`、`handler`，沿用同源检查和 Chat slot 范围；只有用户点击才执行打开，返回的 handler 在执行时重新验证。不接受网络共享、设备路径或任意程序命令。代码块不自动链接，不把 Provider 的 `sandbox:` 链接假定为本机文件。旧产出下载接口保留兼容，但对话中的该接口链接转为本地入口。

## 对话产出管理

Files 面板仅保留项目文件搜索栏（含显示忽略文件、刷新按钮）和项目文件树，不再显示“项目文件 / 产出文件 / 记忆”切换栏。产出查询与下载 API 仍保留，支持当前对话、当前工作区、所有工作区范围；来源对话删除后仍保留的文件会标记来源已删除。“当前对话”和“当前工作区”只读取各自的文件夹；“所有工作区”要遍历整个数据目录并重建汇总索引，工作区很多时需要一两秒（服务端同步完成，期间其他请求会等待）。工具调用之后只更新该对话自己在汇总索引里的条目，且只在它的产出确实变化时才更新；删除聊天也只更新该聊天的条目。

临时报告、调研方案、一次性测试脚本及结果、中间文件默认写入对应 Session 的 `artifacts/reports|tests|temporary/`。全局 `data/artifacts/` 和 Workspace 的 `artifacts/` 仅保存可重建的 JSON/Markdown 引用索引，不复制文件。正式源码、维护中的测试和项目文档不改路径，用户指定路径优先。运行时 Prompt 提供实际目录，bash/pwsh 提供 `MYHARNESS_ARTIFACTS_DIR`、`MYHARNESS_TEMP_DIR`；这不是强制文件系统隔离，不自动重写任意 shell 输出路径。

删除对话默认保留产出及来源，勾选同时删除才删除原文件及上层引用。“移除工作区”仍只取消登记，不删除项目或聊天；同样可选择删除该工作区所有产出，不勾选则仍可通过全局产出查询 API 找到。产出删除有运行任务保护和 symlink/junction 检查。完整存储边界见 [STORAGE](../../../docs/STORAGE.md)。

## 长期记忆查看与恢复

Files 面板不再提供记忆查看入口；记忆查询 API 仍可按当前对话、当前工作区、所有工作区汇总 active 和 archive；汇总不改变原归属，也不意味着其他对话的记忆参与当前 recall。查询结果包含正文、来源 ID/路径、保留的已删除对话记忆和待归属迁移数据。归档可通过恢复 API 恢复；恢复前归档当前版本，原归档仍保留。`GET /api/memory` 是查询入口，`POST /api/memory/restore` 恢复归档，拒绝当前 Chat 运行或收尾期间的恢复；恢复和提取使用同一个 Data memory lock。暂未提供永久删除记忆操作。删除 Chat 的产出删除选项不会删除记忆。

## 文件导入与浮层响应

输入框和主视口接受外部文件拖放；`+` → “添加文件”使用浏览器原生文件选择窗口，不限制扩展名（图片也从这里选）。图片继续作为图片附件发送；其他文件通过 `POST /api/files/upload` 保存原始字节到当前 Session JSONL 同级的 `uploads/<随机 ID>/attachment-<文件名>`，附件卡显示原文件名，发送时把完整路径作为上下文引用交给 Agent 的 `read`（沿用已有文本/富文件读取能力，不保证任意二进制都能解码）。`+` 菜单只有两项：“添加文件”“添加文件夹”（英文界面为 Add files / Add folder；文件夹是独立的 `webkitdirectory` 选择框，文件夹里的每个文件各成一个附件）；`@` 提及文件、`!` Shell、`/` 命令面板和手动压缩仍可直接输入或从其他入口使用。附件数量不设上限，单文件上限 500 MiB；不超过 32 MiB 的图片仍作为图片随消息发送，其他文件（及更大的图片）分片上传（`POST /api/files/upload/begin`、`/chunk`、`/finish`，每片 4 MiB），逐个处理，单个文件失败或超限只跳过它并提示，其余照常添加。附件很多时附件区单行横向滚动，不撑高输入框。历史消息里的附件卡：左键点附件名或书本图标（查看全文）把文件作为右侧工作区文件标签打开，Markdown 在那里渲染显示并可编辑保存，其他类型进入对应视图；眼睛图标（预览）只在卡片内展开前 2000 字左右的摘要，Markdown 渲染后显示，其他文本显示原文，图片显示缩略图；只读导出副本没有工作区，查看全文仍在卡片内展开全文。附件卡的元数据（是否存在、大小等）按卡片或侧栏分组缓存，同一批卡片合并成一次 `POST /api/uploads/info-batch`（每批最多 100 个路径，整包 200 返回逐条 `ok`/`error`；旧服务没有该接口时回退逐条 `GET`）。切换 Chat 不会把已开始导入的文件附加到另一个 Chat。移除附件只移除草稿引用，不删除已导入的原始文件。

分支浮层的分支区和 Worktree 列表区按内容自然收缩，达到最大高度后滚动，不为少量条目预留空白。分支标签出现时提前异步加载分支，同一 Chat 重开菜单先显示已有数据再后台刷新，并复用进行中的请求；切换 Chat 不复用其他 Chat 的数据。首次加载尚无数据时不高亮“新建分支”，也不响应 Enter 创建分支。Worktree 在主副本中默认收起、在副本中默认展开，打开分支浮层时后台预取副本列表，同一 Chat 复用缓存及在途请求，展开时重新校验，创建、删除或改名后强制重新读取；副本名称与路径分两行显示。折叠只隐藏界面，不改变工作目录或隔离状态。浮层随内容高度变化保持锚定；定位使用不含动画变换的布局尺寸，复用全站淡入/淡出与折叠动效。`GET /api/git/worktrees` 的仓库检测和 Git 列表读取均异步，不阻塞服务事件循环；写操作规则不变。侧栏按最新列表顺序放置新增会话，同时短暂保留退出行播放高度折叠；指定 Workspace 新建时自动展开所属分组。新增和退出只使用 grid 高度折叠与淡入淡出，不叠加列表重排位移；纯排序变化按固定行高计算 transform，不读取逐行布局。侧栏关闭浏览器自动滚动锚定，不主动纠正 scrollTop，已有行保留原 DOM 节点。斜杠/文件候选以 180ms 的轻微向上位移与淡入出现在输入卡上方，放大编辑器时也不覆盖编辑区；键盘选中项只滚动候选列表自身。

## Worktree 副本：创建进入、分组、删除与合回

- **创建并进入副本**（分支浮层 Worktree 区第一行，不在副本中时显示）：一次性动作，没有开关和命名框。点后用 `task-MMDD-HHmm`（重名加 `-2`、`-3`）从**点击时当前检出的提交**（`POST /api/git/worktrees/create` 的 `base: "head"`）新建分支和副本，再用 `carryHistory: true` 进入：服务端在副本目录新建会话并复制当前会话活动分支的全部条目（`SessionManager.adoptHistoryFrom`），原会话不变；未发送的草稿（文字、图片、引用）由 `restart-state.js` 的 carry 交给输入框，在会话 id 变化时接过去。进入失败时对话留在主副本，空副本用安全删除收回。成功后后台请求主 Agent 命名（`name-ai`），若期间用户已手动命名则不覆盖；模型不可用或忙时保留分支名作临时名。在副本中这一行变为“返回主副本”，对话和草稿一起带回主副本。
- **分组**：主副本始终在最上方；“我的副本”默认展开，按当前、有改动、干净、已合并排序；`myharness-subagent-` 分支的“子智能体副本”单独成组放在最下方并默认收起；“我的副本”和“子智能体副本”都有自己的展开/折叠按钮和数量徽标，复用同一套折叠动效，条目再多也不会把下面的分组挤远。`GET /api/git/worktrees` 为每个非主副本返回 `changes`（未提交文件数）、`ahead`（main 没有的提交数，最多 6 个副本并发读取）、`merged`（合回记录）、`subagent`、`origin`、`archived`、`archivedAt` 和 `archiveReason`。每行只显示一个状态：“未合并”（有未提交改动或未合并提交，悬停看数量）、“已合并”或“已归档”；路径只显示最后两级，悬停看完整路径，“复制路径”按钮复制完整路径。
- **归档（不再删除用完的副本）**：子智能体任务结束时，副本不再被删除——文件夹、提交和未提交改动都留在原处，只从活动列表移到默认收起的“已归档副本”组；副本干净时先 `git checkout --detach` 转成游离 HEAD，把生成的 `myharness-subagent-*` 分支释放掉（随后照旧 `git branch -D`），快照提交仍由副本自己的 HEAD 保住。带未提交改动的副本保留分支，并在归档记录里写 `branchKeptAt`，6 小时内不重复检查。来源在创建副本时记入 `<agentDir>/worktrees/archive/<path-id>.json`（`manual` / `subagent` / `external`）；没有记录的旧副本按“游离 HEAD 或位于系统临时目录”判定为脚本遗留（`temporary`），有分支且不在临时目录的旧副本不动。归档只写这条小记录，不执行 Git 命令；`POST /api/git/worktrees/archive-sync` 由分支浮层打开时调用一次，负责释放干净归档副本的分支（要求空闲与项目信任）。“已归档副本”组里有“恢复到列表”（`POST /api/git/worktrees/archive`，`archived: false`，按记录的分支名 `git checkout` 回去，分支已不存在时从副本 HEAD 重建同名分支）和“清空已归档”（`POST /api/git/worktrees/archive/clear`）：清空是唯一真正删除已归档副本的操作，先安全删除，仍带未提交改动的副本保留并提示，再点“强制清空已归档”（`force: true`）才丢弃。/git → Worktrees 不再列出已归档副本，只显示一行数量提示。
- **删除**：已合并或没有改动的副本，点删除后行内出现“删除？”，再点一次删除；有改动（或改动情况读不到）的副本弹出确认区，写明未提交改动数和未合并提交数，提供“现在去合并”（进入该副本）、“丢弃并删除”（再次确认后删除目录及未提交改动，分支和提交保留）和“取消”（不做任何改动）。删除失败沿用原有的人话说明、错误详情和强制删除流程。
- **合回 main**：对话在副本中时，分支胶囊右侧出现同样式的“合回 main”胶囊。弹层显示未提交改动数和未合并提交数，确认后 `POST /api/git/worktrees/merge-back`：main 有未提交改动则拒绝；副本的未提交改动先在副本中提交（提交信息 `Save copy changes before merging back`，正常运行 Git hook）；在主副本执行 `git merge --no-edit`。冲突时立即 `git merge --abort`，main 保持原样，弹层列出冲突文件并让用户选择：“保留副本的改动”（`-X theirs` 重试）、“保留 main 的改动”（`-X ours` 重试）、“交给智能体处理”（向当前副本对话发送一条请求，让智能体把 main 合并进副本分支、解决冲突并提交，之后再点合回）或“取消”。合并成功后副本写入 `worktrees/merged/` 记录并保留，当前对话带着历史和草稿回到主副本继续。已合并副本是只读留档：`/api/prompt` 和 `/api/bash` 在已合并副本中返回 409；胶囊变为“已合并 · 回主副本”，点击把对话带回主副本。
- **侧栏按空间显示**：会话列表和 slot 状态带 `copy` 标记（`cwd` 是否在 `<agentDir>/worktrees/<仓库>/<分支>` 内）。当前对话在副本中时，侧栏上方只显示副本中的对话（Default 组改名为“副本中的对话”），主副本的工作区和对话收在底部默认收起的“主副本中的对话”；回到主副本时反过来，副本对话收在底部的“副本中的对话”。进入、返回或合回后侧栏自动跟随，不需要手动点。

## Worktree 副本启动与显示名称

分支浮层的已有副本行悬停或键盘聚焦时提供“进入修改”“启动副本”、重命名、复制路径和删除（删除的确认方式见上一节）；主副本不提供删除，当前副本或任务运行时禁用删除。复用现有 Worktree 删除接口，失败保留副本和确认区：原因与下一步以人话常驻显示，原始报错收在默认折叠的“错误详情”。只有匹配到 `contains modified or untracked files` / `use --force` 的未提交改动拒绝时，才提供显眼的红色“强制删除副本”；点后先显示二次确认，明确永久丢弃副本目录、未提交改动和新增文件，分支保留，再点才发送 `force: true`（`git worktree remove --force`）。未知、权限、锁定等错误不误称脏副本、不随便提供强制按钮，而提供对应说明、“重试删除”和“取消”。强制失败仍保留确认和人话原因，成功刷新副本及分支列表。删除接口的安全与强制路径都检查请求所属 Chat 的信任、运行/收尾/Git 操作状态，且不能跳过当前副本与主副本保护；这不等于检查其他 Chat 或独立副本服务的全部占用。进入修改会在副本目录新建 Chat，但不自动登记工作区：未登记副本的 Chat 放在 No Folder，已登记目录沿用现有工作区，返回主目录也沿用主目录已有登记；已有工作区不自动移除。启动副本在当前浏览器打开具名的新标签页，服务端用 Node 直接运行所选 checkout 自己的 `packages/coding-agent/src/web.ts` 与 `scripts/dev-fast-loader.mjs`（`--port 0`），从启动日志中的 `MyHarness Web UI: <url>` 取得地址并校验服务身份；副本缺少这两个文件时拒绝启动。重复点击复用已确认身份的服务，并尽量聚焦原标签页；页面刷新或浏览器限制可能导致重新打开标签页，但仍连接同一个服务。弹窗被拦截时明确报错，标签页/窗口形式由浏览器设置决定。

`/git` → Worktrees 中的“删除副本”也使用同样的独立确认、人话报错、折叠错误详情与显眼“强制删除副本”入口；强制前再次确认、默认选中“取消”，不会删分支或执行 Combine。两处复用 `web/js/git-delete.js` 的失败说明；API 在本地错误对象的 `rawMessage` 保留服务端原因，避免界面语言转换（特别是英文界面中的中文分支名/路径）丢失 Git 关键词。

管理启动仅支持 Windows MyHarness 源码副本；副本必须包含新版本的服务身份协议。旧副本或其他项目会拒绝启动，需要先更新副本代码。首次缺依赖时沿用副本自身启动器的安装流程，不共享或链接主版本的 `node_modules`。服务端口由系统分配；每个副本在 Agent 目录的 `worktrees/services/<path-id>/` 保存独立 Agent 配置、Session、data 和启动日志。模型与凭据等配置首次启动时复制为私有快照（包含敏感凭据，不能提交或公开）；之后副本修改不回写主配置。这是运行数据分离，不是文件权限沙箱，工具仍可访问其权限允许的其他目录。

同一 checkout（按 Chat 的 `cwd` 区分）新建或切换 Chat 时，先继承本页最近读到的 Git 状态，后台仍在每次激活后重验；临时请求失败不清空已知分支，不跨 Worktree 继承。Files 面板在同一 `cwd` 内切换 Chat 保留已展开目录，目录与搜索使用有界内存缓存及在途请求去重，改动装饰并发读取工作区与当前轮状态；原 Git 变更监听继续刷新。命令面板与全局搜索的输入过滤等待 150ms，搜索与大历史投影分批让出主线程。超过 400 条、或 400 条以内但服务端还有更早消息（首屏尾页 `hasMore`，61–400 条同样适用）且无匹配投影缓存时，先同步构建有限尾窗（最多向前寻找 120 条内的用户消息边界）作为首屏，后台完成完整投影；更小且完整的会话同步构建，但只有 8ms 的帧预算，超预算时退回同样的尾窗预览，由后台单飞构建补全。本会话一旦有完整投影就不再退回尾窗，流式更新只让它最多落后一次投影，上一个投影落地后立即开始下一个。是否需要后台重排只看“屏幕上的投影是不是这批数据（items / 工具状态 / cwd）做的”，不按条数或首屏页大小判断：分页首屏会因向前对齐用户消息而短于一页（`hasMore` 仍为真），按条数判断会让这类会话的后台重排永远不再发生，新消息只进数据不显示。轮次 key 只取条目自身标识（entry id，其次时间戳，都没有才用下标），首屏尾窗换全量、上翻补充旧页都不重挂载；替换首屏尾窗时按替换前的高度补偿滚动，贴底时仍跟随底部；保留每帧分批挂载。长 Markdown 按顶层块分批解析，但单个超大块的词法分析和高亮仍可能产生长任务，不保证全站毫秒级延迟。

浏览器标签标题跟随当前激活 Chat 的 Git 状态实时更新：主工作区使用 `MyHarness-{分支名}`，关联 Worktree 使用 `worktree-{副本显示名或分支名}`；名称以 `myharness-` 开头时替换为 `worktree-`，不再拼接 MyHarness、主版本标记或聊天标题。进入副本和返回主工作区后读取新 Git 状态并立即更新标题。副本页面顶栏的服务身份标记仍来自实际启动目录，悬停显示完整名称和启动目录，不随 Chat 切换改变。副本显示名保存到 `worktrees/names/<path-id>.json`，不修改 Git 分支或文件夹；未命名时用分支名，游离副本用目录名。创建时可填名称或选择主 Agent 命名；自动命名使用当前选中的主模型和当前任务文本，无工具调用，结果先预览，用户保存后才生效。选择自动命名的创建流程先创建副本并停在名称确认，不自动进入；用户保存后可选择进入或启动。已有副本同样可手动改名或请求 AI 建议，手动名称不会被自动覆盖。

设置 → Network 新增 **Copy tab exit delay (seconds)**（`worktreeShutdownGraceSeconds`，0–3600 秒）。首次沿用现有主退出值，之后独立保存；主退出值首次修改时保留副本原值。最后一个副本 SSE 页面断开后按该设置退出，至少等待 5 秒保护刷新；还有页面连接时不会退出。副本倒计时读取主配置中的这一设置，主版本不受影响。

上下文用量浮层与 Session 容量区直接读取当前 Chat 的实时快照（budget 优先，usage 兼容回退）和 Session 统计。打开时立即显示已有数字，不再请求 `/api/context` 或显示整块空白转圈；缺失数据用 `—`，真实零保留为零。容量随现有 SSE 更新，切换 Chat 不复用上一 Chat 的值。详细上下文拆分接口仍保留给需要拆分信息的调用方。

服务端消息投影按 Chat 缓存完整结果或最近一个分页窗口，追加记录、重绑会话时立即失效，并检查分支一致性；快照中的运行/对话框状态保持实时读取，不以缓存冻结任务状态。

Changes 面板在会话切换的临时目标（`pending:` slot）阶段只显示加载占位，不发送变更或 Diff 请求；真实 slot 到达后，即使 Session ID 没变，也会自动加载。请求显式绑定 slot，旧目标的迟到响应不会覆盖新目标；切换目标时不显示上一会话的文件列表或 Diff。手动刷新仍强制重验，真实读取失败保留错误和刷新入口，不把包含“Loading”的真实错误当作正常等待吞掉。

Git 状态轮询按同一 checkout 复用短期只读结果及进行中的查询：仓库/HEAD 检查最多复用 2 秒，未提交预览最多 1 秒；身份、Git 目录布局和版本检测分别复用 10 秒、60 秒和 5 分钟。`GET /api/git/status?fresh=1` 绕过旧结果，多个并发刷新共享同一批新查询；Changes 工作区列表和批量统计也合并并发读取。现有 Git 写接口和工作区失效入口会清除相关缓存；外部 Git 操作在短缓存到期后可见。checkpoint、任务、信任和集成开关仍逐请求读取，不跨 Chat 缓存；提交、撤销、恢复等安全决策继续使用直读，不依赖 UI 缓存。

## 交互耗时检查

浏览器控制台可执行 `const { interactionTimings } = await import('/js/interaction-timing.js'); interactionTimings()` 查看最近 40 次切换的本地测量。`visibleMs` 是目标状态同步完成耗时，`contentMs` 是真实快照和消息到齐耗时，`paintMs` 是两次 animation frame 回调后的绘制机会估计，不等于浏览器实际呈现时间，也不是 INP。记录只在本页内存保存，不包含消息、路径或标题，不上报遥测。视觉确认以 100ms 为目标，真实内容加载单独验收；不得以占位状态冒充内容已就绪。

## 本地运行状态与语言模块

提交/推送中的 Chat 纳入有效内容和运行中保护，切换或新建 Chat 不会复用、回收或删除它；快照携带 `gitTask`，切回或重新加载页面恢复当前进度。输入过草稿或添加过附件的 Chat 也不再视为完全未使用的空白 Chat。

代码智能语言模块通过 `GET /api/code-intelligence/modules` 读取安装管理器清单，`POST /api/code-intelligence/install` 安装，SSE `code_intelligence_installation` 同步传输百分比、当前归档预计剩余时间与安装状态。共享依赖和语言归档分别显示传输进度，下载完成后仍需校验和解压。未发布、缺少校验信息或需要外部依赖的模块显示不可用原因，不伪造可下载状态；缺少发布信息的模块下载按钮仍可点击，点击后如实提示“下载包尚未发布”，需要自行安装外部依赖或与当前版本不兼容的模块按钮禁用。语言模块在设置里是折叠列表（折叠行只有语言名称和状态，点开后在下方显示功能说明、环境依赖和操作区；说明文字随界面语言显示中文或英文）；下载并校验安装完成后，操作区的下载按钮换成启用/停用开关，由 `POST /api/code-intelligence/language`（`{ id, enabled }`）写入 `codeIntelligence.disabledLanguages`；语言模块管理行为保持不变。Symbols 开关由 `codeIntelligence.symbolsEnabled` 控制，默认关闭，修改开关或安装/启用模块后都需重新启动运行时生效（当前工作区运行时在创建时组装语言服务器）。下载包先以原始 `.zip` 文件名放进暂存目录；解压优先用系统自带的 `System32\tar.exe`（能处理超过 260 个字符的路径，大型运行时放进用户目录后会超过这个长度），没有它或失败时才回退到只接受 `.zip` 扩展名的 `Expand-Archive`。

桌面通知区分需要确认、需要回答、成功完成和异常中断；浏览器和系统回退通知共用任务归属、正文结论或错误原因及产出概要，正文按预算主动精简，不仅显示项目名和 Markdown 标题；页面弹窗（桌面端原生通知与浏览器通知）的正文只保留第一句要点，去掉换行并压到约 60 字，服务端回退的 PowerShell 弹窗仍显示完整的任务归属、结论与产出概要。

## 从 Session 面板重启服务

Session 面板底部的“重启服务”替代原“重新加载资源”按钮，调用现有 `/api/restart`。输入框命令 `/reload` 与该按钮等价（同一确认框、同一阶段轮询、同一草稿交接；任务运行中同样被拦）。点击先确认；重启状态在按钮原位显示转圈与阶段文字，不显示顶部重启横幅、不遮挡标题或正文，期间禁止发送但保留草稿。成功用短暂提示反馈；失败在按钮下方保留错误与重试入口。普通断线提示占据独立布局行，不覆盖顶栏。所有已打开 Chat 的前台任务都必须空闲（包括文件/记录收尾和 Git 操作，不包括后台记忆维护）；服务重启恢复发起请求的 Chat，空白但可持久化的 Chat 也会先写入保留标记。页面等待 `/api/boot` 的实例 ID 改变、状态 ready 且原 Session ID 匹配后自动整页刷新，重新加载最新 JavaScript、CSS 和界面资源。刷新前把草稿（含附件）和页面布局暂存到当前标签页的 sessionStorage，刷新后仅在原 Session 匹配且暂存未超过 5 分钟时恢复并清除暂存，再提示成功；Terminal 的旧选中实例不恢复。暂存失败时保留原页面与草稿并显示错误，不强行刷新；90 秒内服务未恢复则显示错误。真实 Shell Terminal 进程仍随旧服务关闭，不是进程热迁移。资源热加载 API 保留，但该按钮不再调用它。

Windows 重启经隐藏 PowerShell `Start-Process` 启动原 Node 入口、相同端口和 Session，移除已不支持的 `--web` 参数；保留 offline、Trust 和资源禁用标志，不重发命令行初始消息。启动日志写入当前 Agent 目录的 `web-restart.out.log` / `web-restart.err.log`。

## 启动

```powershell
# 日常使用：桌面端（Windows 源码 checkout）
.\dev-desktop.cmd
# 命令行直接跑源码（在仓库根目录执行，日志打印实际地址）
node --import ./scripts/dev-fast-loader.mjs ./packages/coding-agent/src/web.ts
# 或已构建的启动入口
myharness
```

| 参数 | 说明 |
| --- | --- |
| `--port <n>` | 端口，默认 `7878`；被占用时依次尝试后面的 10 个端口；`0` 表示由系统分配。 |
| `--no-open` | 兼容保留（桌面端仍在传）：服务启动本来就不会打开浏览器，只在日志打印 `MyHarness Web UI: http://127.0.0.1:<port>/`。 |

服务启动后不会打开任何浏览器；唯一会打开系统浏览器的是 Provider OAuth 登录跳转。原先用系统浏览器打开界面的启动脚本（`dev-web.cmd`、`dev-web.vbs`、`dev-web.ps1`、`web-runtime.ps1`、`web-source.ps1`、`web-source.sh`）及其唤醒接口 `POST /api/wake` 已移除，界面代码的提交历史另存于私有仓库 `h3327725338-star/MyHarness-WebArchive`。

**启动耗时**：源码运行用 `node --import scripts/dev-fast-loader.mjs` 直接运行源码（Node 原生类型剥离）。此前用 `tsx` 时，约 1600 个模块逐个经过转换 hook，从进程启动到服务监听要 11–12 秒；现在约 2.3 秒。服务用页面里的 **Quit MyHarness** 结束，整棵进程树一起退出。`myharness` 同样启动 Web；旧 `dev.cmd` 与多界面切换参数已移除。

其余参数照常生效：`--session`、`--continue`、`--model`、`--thinking`、`--no-extensions`、`--approve/--no-approve` 等；命令行里的初始 message / `@file` 会在启动后作为第一条消息发送。终端里按 `Ctrl+C`（或界面里的 **Quit MyHarness**）会停止服务并结束当前任务。

**服务的生命周期**：只要还有至少一个浏览器页面连着（以真实的 SSE 连接为准，所以浏览器崩溃、被强制关闭也会被发现），服务就一直运行。最后一个页面断开后，服务等待一段宽限时间再退出；在这段时间内刷新（F5）或重新打开页面会取消退出。宽限到期服务退出后，还开着的其余页面会显示顶部黄条“与本地服务的连接已断开，正在重连…”（`app.js`，条件是没在重启、曾经连上过、当前连不上），因为进程已经不在，重连永远不会成功，每个失败的请求也会弹右下角的红色提示；这时需要重新启动服务（`myharness`）。宽限到期时如果还有任务在运行（与“Restart service”同一判据：任一会话非空闲、有待报告的结果或 Git 操作），倒计时不会触发退出，而是重新等待一个宽限期直到任务停下，绝不中断进行中的工作。宽限时间是设置项 **Web UI exit delay (seconds)**（`webShutdownGraceSeconds`，设置 → Network，默认 10 秒，范围 0–3600 秒，实际等待至少 5 秒以保护刷新与 SSE 重连（包括配置为 0 时）；配置超过 5 秒时按配置等待），每次开始倒计时时重新读取，修改后对下一次生效。从未有页面连接过的服务（例如 `--no-open` 刚启动）不会倒计时。只管理这一个 Web UI 服务自己，不会结束任何 CLI 进程，也不会按名字批量结束进程。倒计时结束时服务的退出方式与 **Quit MyHarness** 相同。页面的事件流（`/api/events`）在服务返回失败状态而被浏览器永久放弃后，会由看门狗（`sse-watchdog.js`）自动重建，标签页切回前台时也会立即尝试；服务重新监听同一端口后无需刷新页面即可自动重连。另外，发送一条消息后，如果它几秒内没有真正落地（页面上只有乐观行、被清掉后什么也没有，或消息已经进了数据但聊天区还没把它画出来，`store.js` 的 `verifyLiveUpdates` 同时检查数据与上一次真正画出的轮次），页面会重建事件流并重新读取快照与 transcript，所以消息和回复不会因为事件流静默而只能靠手动重启服务才出现。

服务只监听 `127.0.0.1`，面向 Windows 桌面浏览器，单用户使用。不提供手机/平板适配、局域网访问或多人协作。

## 界面结构

```text
┌ 侧栏 ──────┬ 会话 ──────────────────────────────┬ 详情面板（可开关，可拖宽）┐
│ Workspaces │ 标题 · 状态 · 面板按钮               │ Changes │ Files │ Terminal │ Session │
│  └ Conversations│ 对话（安静阅读） + 运行摘要          │                          │
│            │ Composer（模型/推理力度/发送/停止）  │                          │
└────────────┴─────────────────────────────────────┴──────────────────────────┘
```

* **侧栏**：真实的 Workspace / Chat 结构（`WorkspaceStore` + `SessionManager.list`）。新建 Chat、切换 Chat、重命名（手动或 AI 生成标题）、删除、添加/移除 Workspace。**“从列表移除”只取消 Workspace 的登记**（任何时候都可以，包括当前和最后一个 Workspace）：磁盘上的项目目录、项目文件和 Session 数据都不动，原来属于它的 Chat 继续存在，只是变成不属于任何 Workspace 的 Chat，出现在侧栏的 **Conversations / 对话** 分组（旧版本曾显示为 No Folder），仍可打开、继续对话；之后再添加同一个文件夹，会接回它原来的 Chat。**Conversations**（旧版本曾叫 No Folder / General）只是侧栏里的一个逻辑分组，和普通 Workspace 一样可展开/收起（默认展开），但它不是 Workspace：没有文件夹、不在 Workspace 登记里，其中 Chat 的磁盘位置和归属都不变。它列出所有不属于 Workspace 的 Chat（新建时没有选 Workspace 的，以及被移除的 Workspace 留下的），分组行右侧的 `+` 新建这样的 Chat；列表只在真正请求中才显示“Loading…”，请求失败（例如正在运行的服务比页面旧、没有 `GET /api/sessions/unbound`）会显示原因和“Retry”，Workspace 的 Chat 列表同理；侧栏顶部的 New chat、`Ctrl+Alt+N` 和命令面板里的 New chat 总是新建一个不属于任何 Workspace 的 Chat（`actions.newChat`）：它立刻作为当前 Chat 列在 Conversations 里（还没有消息时显示为 “New chat”，此时没有重命名/删除菜单），该分组处于收起状态时会自动展开；要在某个 Workspace 里新建，用该 Workspace 行右侧的 `+`。斜杠命令 `/new` 不变，仍沿用当前 Chat 的归属。没有任何 Workspace 时输入框、Provider、Model、Agent 和 New Chat 都照常可用。Workspace 可展开/收起（带高度动画，不影响其中正在运行的 Chat）。Workspace 行的更多菜单支持“重命名”：名称就地编辑，Enter 保存、Esc 取消；只保存显示别名，Workspace ID、磁盘路径和 Chat 归属不变，并广播刷新所有页面。新建的空 Chat 出现和离开后的清理使用同一套高度与淡入淡出动效。状态标记固定在 Chat 行最左侧（标题文字之前）的一个常驻 16px 槽位里，不会挤动标题，也不会挤占右侧时间：行尾的相对更新时间（“刚刚”“9分”等）任何时候都显示，状态变化不再隐藏它。运行中是小的空心旋转圆环，运行彻底结束时圆环停止旋转并平滑淡出；后台自动命名进行中是它自己的柔和呼吸微光小点；两者并发时共用同一个槽位呈同心结构——外环旋转指示运行、中心内嵌呼吸小点指示命名，命名完成后小点平滑淡出、标题就地更新。等待你回答是一个中性色的时钟小图标（形状与未读圆点不同，不靠颜色区分），**已完成但你还没看过的结果**是蓝色实心圆点，看过之后消失（已读且空闲的 Chat 没有任何标记）。圆环与小点的颜色、光晕全部取自当前主题的强调色与边框变量，三套配色方案下自动适配，不写死任何颜色。Workspace 名称右侧的蓝点表示其中有未读结果。“看过”＝该 Chat 正显示在页面上且页面可见；未读标记由服务端按 Chat 保存（`SlotStatus.unread`，页面通过 `POST /api/seen` 上报），多个 Chat 并发时互不影响，未读的后台 Chat 不会被回收。还没写入磁盘的进行中 Chat 也会列出，随时可切回。Workspace 分组只挂载可视区附近的分组（前后各多留约一屏，`sidebar.js:238` 的 `WINDOW_OVERSCAN`），其余用同等高度的空白占位，滚动条行为不变；筛选仍匹配全部 Chat，只渲染窗口内的分组。收起时挂的是侧栏自身的 `is-collapsed`（`layout.css:15`），主区随网格轨道同步重排。启动首屏先读当前聊天与 Workspace 列表，“Conversations”与“已归档”列表推迟到首屏读完、页面空闲时再读（`store.js:749` 的 `scheduleAuxLists`，`requestIdleCallback` 兜底 2.5 秒，`store.js:818`），展开分组时直接读、不等空闲。Workspace 的 Chat 列表优先读该 Workspace 会话目录下的 `.sessions-index.json` sidecar（缓存 id、标题、更新时间、条数和首条用户消息预览），会话写入后 300ms 防抖原子更新，目录 mtime * **添加 Workspace**：Coding 模式下侧栏的 `+` 和 `/workspace` 里的 “Add workspace” 直接打开 Windows 自带的文件夹选择窗口（与资源管理器相同，只能选文件夹），选中后把该文件夹登记为 Workspace，取消则什么都不做。General 模式下侧栏的 `+` 先就地展开轻量下拉菜单（复用全站 Popover/Menu 动效与主题变量）： “新建工作区”弹出命名弹窗（输入框自动聚焦，Enter 提交、Esc/点击遮罩取消），在当前或首个 General Workspace 的上级目录下创建真实子文件夹并登记（`GET /api/workspaces/create-target` + `POST /api/workspaces/create`，非法名与重名在弹窗内拦截、不覆盖）； “选择本地已有文件夹”走原来的系统窗口流程。新建成功只在列表插入节点，不自动建对话、不抢焦点。窗口由本机服务打开（`POST /api/fs/pick-folder`，`folder-dialog.ts` 通过 Windows PowerShell 调用系统的 `IFileOpenDialog`，在独立进程里运行，不阻塞服务），显示在浏览器窗口前面；同一时间只开一个。登记仍走原来的 `POST /api/workspaces/add`。没有系统窗口的平台（接口返回 501）才退回页面内置的文件夹选择器：类似资源管理器——后退/前进/上一级、可编辑并可点击的路径（面包屑）、快速访问（主目录/桌面/文档/下载）、盘符、已有 Workspace、筛选、新建文件夹、显示隐藏文件夹；只列目录，选中后显示完整路径再确认。
* **对话**：用户消息、运行摘要、最终回复。一轮回复按发生顺序排列：连续的思考和工具调用是一个可折叠块，模型写出的正文平铺在块之间；正文之后模型再次思考或调用工具时，在这段正文下方新开一个折叠块（`turns.js` 的 `turnSegments`）。分段只影响显示，底层 SSE、Session 和模型上下文仍是同一轮。正在接收输出的块自动展开，输出转到正文或结束后自动收起；用户手动展开或收起过的块保持用户的选择；打开历史 Chat 时按默认展开配置显示。前面的块只显示各自的动作数（例如 `7 个操作`，只有思考的块显示 `Reasoning`），使用中性的列表图标，不显示“已完成”或任务结果图标；当前最后一块显示进行中的动作和计时。任务结束后，最后一个块显示整轮的结果、用时、操作总数和改动文件数，而不是只统计最后一段。只有一个块时同样显示整轮统计。用户消息复用回复的安全 Markdown 渲染器，支持标题、列表、代码、粗体与斜体，并保留正文里的普通换行；回复和文件预览仍使用标准 Markdown 换行规则。复制与编辑仍使用原文。默认不展开 Thinking、读文件、搜索、命令和编辑，只显示一行摘要，例如 `Worked for 32s · 9 actions · 4 files changed`。回复下方的小字显示模型和这次回复的 Token 数（`12.7K tokens in / 0.2K tokens out`；千用 `K`、百万用 `M`，固定保留一位小数，例如 `11.6M`）。还没有名称也没有消息的新 Chat，顶部栏不显示标题，只显示 Workspace。用户主动向上滚动离底超过 72px 时，对话区底部正中出现一个只有向下箭头的圆形按钮，点击后平滑滚到最新消息。触底判定保留 10px 容差；内容增加、卡片展开收起和视口尺寸变化会重新核验并保持贴底，不会单独触发按钮；展开文件 Diff 行或导出副本里附件卡的全文时例外，被点击的那一行保持不动、内容在它下方展开（不跟随到底，手动滚动或收起后恢复）。正文和 Thinking 的流式长文本（16,000 字符以上，`web/js/markdown.js` 的 `LARGE_TEXT`）分段渲染：已经排好的块排一次就不再变动，还没轮到的部分先用与正文同字体、同样换行的纯文本顶上（`div.md-pending`，样式在 `web/css/transcript.css`），流式结束时沿用同一个渲染实例把全文补齐，所以同一位置不会在等宽占位和正常排版之间反复跳动；大文本解析是增量的（每次仍重新 lexer 以保证块结构精确，只有变化的尾部 token 重新渲染，引用式链接定义出现时全量重排）。
  * 运行步骤遵循“对话与调度”里的默认展开配置。正文输出和任务结束不重建步骤区，用户主动展开或收起的状态优先；收起总摘要再展开时保留内部子项状态。展开/折叠复用统一的高度与淡入淡出动效，动画关闭设置仍然生效。侧栏分组点“再显示 n 个”全部展开后，超过 12 条时聊天区固定为 12 行高、在区内滚动（`overscroll-behavior: contain`，不带动侧栏），虚拟列表的分组估高按同一上限计算；不足 12 条不加高度框，也没有“收起”。用户自己发出的消息按 Markdown 渲染后的真实行高判断，超过 8 行时折叠为 6 行、底部渐隐，“显示更多”展开后可再收起；模型回复不折叠。Markdown 引用块比正文暗一档底色（`--quote-bg`）、强调色竖线、字号小一号。就地替换内容的“Show all / Show more / Show less”（工具结果列表、命令输出、Diff、导出副本里附件卡的读取全文（加载提示换成全文内容）、侧栏的“再显示 n 个”）没有隐藏的内容可以展开，改为在替换前后各量一次高度，用同一动效在两个高度之间过渡（`useHeightGlide`）；动画关闭时立即显示。
  * 第一层：摘要行（`Worked for …` / `Failed after …` / `Partially completed` / `Cancelled after …` / 运行中显示当前动作）。请求已发出、模型还没有返回任何步骤时，这一行只有旋转环、当前动作和计时：没有展开箭头，下面也没有空的步骤区和占位文字；出现第一个步骤后才变成可展开的行。上下文压缩进行中时，这一行不再重复显示压缩：没有旋转环、当前动作和计时（还没有步骤时整行不出现），手动压缩时上一轮保持完成后的样子；压缩只显示在输入框上方的状态条里——“Compacting context (manual)”（简体中文：`正在压缩上下文 (manual)`）、已用时间（例如 `2m 4s`）和 Cancel，文字末尾不加省略号。状态条里的操作（Provider 出错倒计时条的 Cancel retry、压缩条的 Cancel）是同一个单行紧凑控件：微弱底色加细描边、颜色随条子文字、flex:none 永不折行，与左侧文案垂直居中；左侧长文案永远单行省略号截断，不会把按钮挤成竖排。压缩开始后才打开的页面没有 `compaction_start` 事件，状态条按快照的 `flags.compacting` 显示，不带原因。
  * 第二层：点开后是可读步骤。读文件、搜索、命令、编辑等用自然语言描述，连续同类动作聚合（“Read 8 files”），可继续展开单项；同一种工具永远是同一种样子（图标、字重、右侧的数字、展开方式），与它走哪条调用路径无关（`web/js/tool-rows.js`）。步骤之间只有确实存在下一步时才画一条很细的竖线，从上一步的状态图标连到下一步的；空状态和只有一步时没有线。进行中的步骤（包括摘要行里的当前动作，如“正在请求模型”）左边是一个小的旋转环；完成的步骤显示该类工具自己的图标，失败是红色的感叹号圆圈，被中止的是停止圆圈。编辑/写入的行右侧是真实的 `+N −M`：`write` 返回新增/删除行数（新文件的 `+N` 是它的行数），`edit` 返回 patch，行数从 patch 数出来；没有真实数字的行不显示。运行步骤未知行数时不显示 `+0 −0`。`edit` 在模型生成参数时按已收到的替换文本计算增删行数，并明确标记“预览”：这是替换片段的当前变更，不代表已应用文件 Diff，最终数字以工具校验和结果为准；只生成 `oldText`、尚无 `newText` 时不报数。预览计算限制为每次 64,000 字符、100 个替换块，超过限制等待工具统计；`write` 生成期间没有文件基线，不猜测增删行数。状态区分准备修改、生成修改和应用修改。数字每 200ms 检查最新样本，滚动动画仍为 360ms，绿色新增向上、红色删除向下；预览变化和生成/校验/结果阶段的校正直接更新，可靠统计增加时才滚动。暂时缺少进行中统计时保留上一份数值并标为预览，不当成零扣除。密集更新只保留最新样本，当前动画完成后再显示最新值，不打断、不回放旧样本。失败或取消时，扣除未成功应用的统计也播放动画，已完成且未变化的数字保持不动；零值项在动画结束后隐藏，不残留 `+0` / `−0`。历史记录首次显示不播放动画，动画关闭设置仍生效。`edit` / 本地 `write` 在验证内容后、原子写入前通过工具进度报告真实变更集，进行中的数字表示待写入变更而非逐行落盘进度；写入失败时不保留该预览。没有可靠统计的工具不估算数字，也不为动画拆分原子写入。网页搜索与网页读取聚合成一行，例如 `2 search rounds · 18 results returned · 3 pages opened`（简体中文：`2 轮搜索 · 返回 18 个网页 · 打开 3 个网页`）：数字来自各次 `web_search` / `web_fetch` 返回的 details（搜索次数、各次返回的网页数之和、各次真正打开的网页数之和），展开后逐次列出搜索词、返回的网页、打开的网页和失败原因，没有记录的数字不显示。Thinking 有内容时可展开；sub-agent / workflow 显示阶段与任务进度。
  * 第三层：单项的 Raw details——真实 tool name、arguments、stdout/stderr、exit code、耗时、result details。读取的文件是 Markdown（`.md` / `.markdown` / `.mdx`）时，展开后的结果按 Markdown 渲染（复用对话里同一个渲染器）；其他文件（`.cpp`、`.ts`、`.json`、日志、shell 输出等）保持原样的等宽文本，不会被当作 Markdown 解析。tool 名称、参数、耗时等元数据始终是普通界面。结果正文下面的“结果详情”（result details）与正文之间有一条分隔线，采用扁平排布：小号标题分隔、无嵌套卡片边框；卡片头是可点击的一行（箭头、标题、右侧的 Show / Hide），展开和收起用统一的折叠动效。结果详情过大时（服务端已替换为截断标记）显示一句安静的说明（`web/js/transcript.js:151-154`），不展开原始字段。命令输出与 Markdown 读取结果过长时只显示前一段（等宽输出 20KB、Markdown 60KB，`web/js/transcript.js:90-106`），“Show all”按 100KB 分块追加（`SHOW_ALL_CHUNK`，`web/js/transcript.js:34`），超过 200KB 的 Markdown 不再走解析器、保持等宽纯文本；超大工具输出走服务端的区间读（`GET /api/tool-output` 的 `offset` / `limit`，首块默认 512KB、累计窗口 4MB，`src/modes/web/routes-files.ts:162-163`）。`*** Begin Patch … *** End Patch` 包成一个 diff 代码块显示（`web/js/markdown.js:92` 的 `wrapPatchBlocks`），而不是散段落。输入框缩略图与正文图片点击后共用同一个全屏图片灯箱（`web/js/lightbox.js:30` 的 `openImageLightbox`，`ImageLightboxHost` 挂在根上）：深色遮罩（z-index 600，`overlays.css:279`）+ 居中大图（最大 90vw/vh），Esc、点击遮罩空白或右上角关闭按钮退出，Tab 只停在关闭按钮上，关闭后焦点回到打开前的位置；缩略图右上角的 ✕ 只删除附件，不会打开灯箱（`composer.js:679` 先排除 `.thumb-x`）。
  * **文件变更摘要卡片**：任务确实改了文件时，这一轮的末尾（最终回复之后）出现一张卡片：标题 `Edited 2 files` 和总计 `+4 −2`，下面每个文件一行，右侧是它自己的新增（绿）/删除（红）行数；二进制、过大或缺少基线的文件只显示文件名，不显示行数（此时也不显示总计）。**每个文件行可以点击展开/收起**（统一的折叠动效），展开后是这个文件的行级 Diff（行号、绿色新增、红色删除、语法高亮，复用 Changes 面板的 `DiffView`，在卡片内自己滚动）；Markdown 文件（`.md` / `.markdown` / `.mdx`）自动把连续的未改动/删除/新增行分别按 Markdown 渲染，不再提供视图切换按钮；其他文件保持代码 Diff。**卡片按轮次保存在 Session 里**：任务结束时（`WebHost.recordRunChanges`）把这一轮改动的文件、行数和当时的 Diff 写成一条 custom entry（`web-run-changes`，不进入模型上下文，与 `web-git-status` 同类），wire 里是 `runChanges` 项，挂在它所属那一轮的回复下面。所以继续发起新任务时旧卡片保留在原位，新任务结束后在新回复下面追加新卡片，每张卡片只包含自己那一轮的改动；刷新页面、重启服务后仍在。上一轮未提交的改动不会计入后续纯问答，也不会重复生成卡片；下一轮修改会建立新的 Git 检查点，以修改前的工作区为基线，Undo 本轮时保留之前的未提交内容。旧检查点仍保存在磁盘，纯问答不会关闭此前的 Undo / Commit 入口。展开时通过 `GET /api/changes/card-diff?id=…&path=…` 读取随卡片保存的 Diff；单个文件超过 20 万字符或一轮合计超过 100 万字符的 Diff 不保存，此时回退到本次服务进程里的任务记录，没有记录则提示 Diff 过大未保存。卡片不会打开右侧面板（面板只由顶栏的按钮打开，见下面的“详情面板”）。这项功能之前的旧任务没有卡片；附着到其他进程的会话（mirror）只显示卡片，不写入 Session。任务窗口内 HEAD 前进了、但本轮没跑过会动 HEAD 的 Git 命令（commit/merge/switch 等）时，一律视为并行窗口或用户在外部的提交：不计入本轮卡片和改动数，只在结果横幅提示（`N 个文件在本轮之外被提交（未计入本轮）`），与这些外部提交重叠的工作区差异也不归属本轮；本轮自己提交过时沿用旧行为全部计入。同一工作区里其他对话改过的文件不计入本轮卡片和改动数：每个会话在服务端记录自己成功执行的文件操作（edit / write / apply_patch / apply_rename）和运行命令的时间窗，任务结束时把差额里这些记录解释为“别的会话改的”文件静默剔除（`change-claims.ts`，命令行改动按文件最后写入时间是否落在别的会话的命令时间窗内、且不在本会话自己的时间窗内判断）；本会话自己改过、两个会话的时间窗重叠、或没有任何记录能解释的改动一律保留，剔除后不显示任何提示。本进程之外的改动（另一个 MyHarness 进程、外部程序）没有记录，按未归属处理照常显示。
  * 需要用户处理的状态永远不折叠：等待回答/审批、失败、部分完成、取消都有独立的横幅，横幅会说明失败原因、改了几个文件、跑了几条命令（窗口外他人提交单独提示，不计入本轮改动数），并提供 Retry；Retry 不会重发原始任务文本（那会让模型从头重做已完成的步骤），而是发送一条简短的“从中断处继续”指令，携带已有的文件改动与会话上下文接着推进未完成部分，效果等同用户手动发送“继续”（空闲守卫不变：运行中时仍提示先等待或停止）；任务留下了未提交的改动时还有 Undo or commit（打开行内的 `/git` 面板）。
任务收尾状态条位于输入框上方，持续超过 500ms 才显示；仅显示核对文件改动和保存任务记录，不等待长期记忆模型。记忆维护作为独立 `memory_status` SSE 和 `memoryMaintenance` 快照状态，在空闲时通过顶栏小状态显示待处理/后台更新/连续失败；不弹出通知、不禁用发送、不计入 Chat active/completion 或重启保护。前台工作状态优先显示。错误详情可悬停查看。待处理任务落盘后，后台提取及可能的整理与聊天操作并行；重启后重新打开对应 Chat 恢复，不自动加载所有 Chat。

Provider 出错的重试条（以及 Provider 恢复条）同样位于输入框上方，常驻一行：转圈、“N 秒后重试 当前/上限”、一个简短原因，右侧是独立间距的“取消重试”按钮，不被长文本挤压。原因优先用后端分类（`auto_retry_start.errorCategory`，与重试逻辑共用同一份枚举 `ProviderErrorCategory`）：建连超时、无法连接、首包超时、静默超时、连接断开、请求限流、上游过载；没有分类（`other` 或旧事件）时才退回按错误文本猜（请求超时、连接中断、响应为空、上游错误码、请求失败；`web/js/retry-reason.js`）。网络失败的“当前/上限”把第一次尝试算进去（第二次尝试显示 `2/2`，上限即“同一模型最多尝试次数”）。达到上限后切到备用模型时，条上显示“已切换到 <模型名>”，备用模型结束这个任务后消失。完整的错误原文通过悬浮提示查看，点击状态文字可在条内展开 / 收起。

已有内容输出后连接中断（静默超时 / 断连）不会自动重发：已显示的内容原样保留，该任务以“已中断”结束（`run.terminalReason === "output-interrupted"`），结果横幅标题是“已中断”，说明连接在回答过程中断开、不会自动重发，并保留常规的“重试”按钮——它发送“从当前状态继续”的指令，不重做已完成的步骤。

* **生成速度（t/s）与缓存命中**：两个数字都按“每一次模型请求”计算，并经过同样的四种状态：首次请求无可靠数据时显示 `—`（仍保留检测状态提示）；已有可靠数字保留到新请求报告可替换的数据，之后是实时值（带闪烁圆点）、请求结束后的最终值，或者 `—`（没能可靠测量）。
  * 速度只算模型真正输出的时间——从第一个非空流式输出片段（文字、thinking 或工具调用参数）开始计时，内容块开始事件不算，等待首个 Token、输入阶段和工具执行都不算。实时值是最近约 1.5 秒内的吞吐，随每一段流式输出刷新（服务端独立 meter 事件最多每 150 毫秒推送一次，usage 同批携带最新值）：Provider 在流式过程中持续报告输出 Token 数时用它报告的数字；只在结束时报告的 Provider，则按已输出的文字估算（约 4 个字符 1 个 Token，每个中日韩字符约 0.7 个 Token），数值前带 `≈`（快照字段 `speed.estimated`），一旦 Provider 报告了数字就改用它；结束后显示这次回复的平均值（输出 Token ÷ 首个输出到结束的时间；输出包含 Provider 报告的推理 Token，但不重复相加，与 DeepSeek 的输出口径一致），Provider 完全没有报告输出 Token 时平均值也是按文字估算的并带 `≈`。平均值保留到下一次请求取得可靠测量。回复不是流式的或时间太短（< 0.25 秒）时结束为 `—`；任务被停止或失败时，已有的实时值保留为最后一个可靠值，没有数字则是 `—`。最新实时速度由 `generation-speed.ts` 计算，SSE `generation_speed` 推送；会话层 `RequestTimingTracker` 在持久化前记录请求总耗时、首次输出等待、生成时间及工具耗时，统计可从 JSONL 恢复。旧会话缺少计时不会补造。工具累计时间为各次执行之和，并行时可重叠。缓存分项保留缺项；可靠总 Token 减输出可确定完整输入，即使缓存写入缺失也可计算命中率。
  * 缓存命中只用 Provider 在这次请求里报告的 Token：命中率 = cache read ÷（普通输入 + cache read + cache write），Provider 报告了这次请求的用量后显示实时值，请求结束后是最终值。接口明确返回缓存计数为零时，即使是第一次请求也显示真实的 `0%`；没有返回缓存字段时，沿用旧 Session 的兼容判断，否则显示 `—`。Claude（`message_start`）和 Gemini（每个数据块）在回复一开始就带缓存用量，所以是真实的实时值；OpenAI 兼容的 Provider 如果只在最后一个数据块报告 Usage，生成期间显示 `—`，不再根据上一轮输入猜测命中率；收到真实 Usage 后显示实测值，请求中断且没有可靠数字时显示 `—`。悬停数值可以看到这次请求命中的 Token 数和整个 Session 的累计命中率；这个页面还没发过请求（例如刚打开的历史 Chat）时，数值用整个 Session 的累计命中率代替。服务端 `request-cache.ts` 计算，SSE `cache_hit` 推送，快照字段 `cache`。
* **统计格式**：缓存命中固定保留两位小数（包括预估和历史累计值）。Token 数统一用 `util.js` 的 `fmtTokens`：千用 `K`、百万用 `M`，固定一位小数（`187.7K`、`27.1K`、`11.6M`），不到一千显示数字本身；悬停提示、Session 汇总、设置及 Provider 容量说明也使用相同 K/M 格式，不输出原始长整数；编辑字段仍保留原有精度，保存值不变。Session 统计使用“用户 / Agent”；费用没有价格规则或没有可靠正值时显示 `—`（与其他缺省值相同），不把默认零计价当作已确认免费。
* **实时数据**：上下文占用、Session 的消息 / 工具调用计数、输入 / 输出 / 缓存 Token、费用以及 Session 名称和文件由服务端通过 SSE `usage` 推送（`WebHost.broadcastUsage`：每条消息结束、每次工具调用结束、任务开始和结束、压缩结束时发送，流式输出期间与正文同批推送（50ms 合并窗口）；Provider 尚未报告输出用量时按已生成文字估算输出 Token 与对应费用，用 `≈` 标明，结束后由真实用量替换。输入与缓存只使用 Provider 报告的数据）。`store.js` 把它写入 `snap.context`、`snap.session` 和 `stats`，用量环和 Session 面板直接读取，所以右侧面板保持打开时数据随任务实时变化，不需要关闭再打开。

* **详情面板**：属于当前对话——每个对话有自己的标签、当前标签和 Changes 范围，切换对话就换成那个对话的面板，从没开过标签的对话是空面板（见下面的“工作区标签”）。每次打开页面都是关闭的，也没有任何东西会替你打开它：顶栏右上角的按钮（Changes / Files / Terminal / Session）打开、关闭或切换它；此外只有用户在聊天里左键点击文件链接或附件（附件名、“查看全文”按钮）会打开它，并把该文件作为文件标签打开；Changes 角标读取当前 Git 未提交文件数，提交完成并刷新状态后、或工作区干净时归零隐藏，不读取历史任务改动数，通用模式下不显示（那是文件夹的 Git，不属于当前对话）；聊天里的其他卡片、Composer 的标签、斜杠命令都不会打开它。面板从右侧平滑滑入/滑出，对话区同时随之重排宽度；面板内容直接向上顶满显示，右上角保留轻量关闭按钮，亦可通过主顶栏对应图标直接切换或 Toggle 关闭。面板和对话区互不影响：页面只有一行，高度固定等于窗口（`css/layout.css` 的 `.app`），每一栏的内容都在自己那一栏里滚动（面板是 `.panel-body`），所以切换标签、展开/收起面板里的分组或出现很长的列表都不会改变对话区和输入框的位置与高度。面板里的内容不会把面板撑宽：长路径用省略号截断，Diff、文件内容和终端的命令输出按面板当前宽度自动折行（不横向滚动、不截断）。拖动面板左边缘调整宽度，宽度不会超过窗口留给它的空间，拖动从屏幕上的实际宽度开始；拖动时每一帧只改一次宽度，屏幕外的代码行不参与排版（`content-visibility`），终端在停下后才重新计算行列。

  **Project Trust**（安全与隐私页）是一行：项目路径、状态（已信任 / 未信任 / 无需信任）和一个开关。开关打开＝信任这个文件夹，关闭＝不信任；决定保存到 `trust.json` 并立即生效：`POST /api/trust` 保存后先让发起请求的 Chat 按新状态重新加载项目设置和资源，再让同一文件夹里其他空闲的已打开 Chat 跟进（`WebHost.applySavedTrust`、`hub.ts` 的 `trust_changed`）；Chat 正在运行或压缩时返回 409，什么都不保存。项目里没有需要信任的资源时只显示“无需信任”，没有开关。“信任上级文件夹”仍可在行内 `/settings` → Project trust 里选择。

  **通知**（安全与隐私 → 通知，与终端共用 `popupNotifications`）：四项设置——“任务完成通知”（从不 / 仅在未聚焦时 / 始终，默认始终；完成、失败或被中断都算）、“启用权限通知”（需要确认的 confirm 对话框）、“启用问题通知”（select / input / editor 对话框，包括 `ask_user_question`）、“通知提示音”（关 / 轻柔 / 清铃 / 琶音，选中即试听，旁边有“试听”按钮；声音由 `notification-sounds.js` 用 Web Audio 合成）。提示音始终播放；弹窗在“始终”下只在你不是正看着该 Chat 时出现（窗口没聚焦，或当前打开的是别的 Chat），“仅在未聚焦时”下只在窗口没聚焦时出现；权限和问题通知按“始终”的规则。服务端在运行进入终态或出现对话框时（`WebHost.announceTaskEnd` 与对话框回调）通过 SSE `task_notification`（带 `focus`、`sound`，对话框另带 `category`、`detail`）交给打开着的页面，页面先用 `POST /api/notifications/answer` 领下这条通知（`claim`）再自己弹，弹完回报是否成功。桌面端由 Electron 主进程用原生 `Notification`（`desktop:notify`，应用 ID `MyHarness`，静音，声音由页面播放）弹出 Windows 通知：标题是“状态 · Chat 名称”，正文只有第一句要点（问题标题、失败原因或回复开头，约 60 字）；通知不再带正文图标，整块内容区都留给文字，只有顶部那一枚应用图标和名称，点击通知会把窗口带到前台并回到该 Chat（`desktop:notification-click`）。浏览器里打开时改用 Web Notification，需要浏览器授权（把“任务完成通知”改成非“从不”的那次点击会申请权限）。没有页面打开、浏览器没有权限，或页面自己弹不出来时，服务端才改用 PowerShell 系统弹窗（`showPopupNotification`）：2.5 秒内没有任何页面领这条通知（页面太忙，或者根本没在运行），或领下的页面回报自己弹不出来、15 秒内没有结果时，由系统弹窗接手；领晚了的页面拿到 `claimed: false` 就不再自己弹，所以同一个任务只出现一个弹窗。原来只保存在浏览器里的“浏览器通知”开关已移除，由“仅在未聚焦时”取代。

  **保存反馈**（设置页和行内 `/settings` 面板一样，`web/js/settings-apply.js`）：开关、选项和输入框的新值立即显示；本地保存很快，所以什么额外的东西都不出现，只有真的慢（超过约 0.4 秒）的保存才在控件旁显示小的加载圈，显示后至少保持约 0.5 秒，不会闪一下；保存完成后重新读取真实设置，保存失败时值恢复原样并弹出失败原因。**数字类设置使用统一的 80px 窄数字框，单位并入标题**：上下文窗口上限标题为“主上下文窗口上限（K tokens）”与“子智能体上下文窗口上限（K tokens）”（`Main context window cap (K tokens)` / `Sub-agent context window cap (K tokens)`），输入框直接显示数值（如 `256`，80px 右对齐，1K = 1024 Token，去掉了单位方块与换算小字，保存的仍是准确的 Token 数，留空表示不限制，服务端设置项的 `type` 是 `tokens`）；`Web UI exit delay (seconds)` 显示为 `10`，单位在标题中。网络页的 **自动重试次数**是紧凑下拉，选项为 `0（不重试）`、`1–20` 和“无限”；已保存但不在标准列表里的整数会作为额外选项保留，选中的值仍保存为整数或字符串 `"unlimited"`。同一页的“超时与重试”卡片有三个超时行——建连超时（秒）、首包超时（秒）、静默超时（秒）（`network.connectTimeoutMs` / `firstByteTimeoutMs` / `streamIdleTimeoutMs`），单位并入标题，数值框只显示秒，存储仍是毫秒，范围 1–3600 秒，超出范围时框变红、离开时恢复原值并提示（不存在“不限时”）；同一模型最多尝试次数（次，含第一次）（`retry.networkMaxAttempts`，1–20）同样把单位放在标题中。卡片末尾有两行只读文字：一行说明断连不设时限、已显示内容不会自动从头重发；另一行按当前数值给出估算“单次请求最长等待约 X 分钟”（次数 × (建连 + max(首包, 静默))，不足一分钟时按秒显示）。行内 `/settings` 面板对应一个“Timeouts & retries”子页，列出同样四项。输入的值不合法时框变红，离开输入框时恢复原值并给出提示。

  **模型设置项**（Compact Model、Fallback Model、Conversation Naming、Auto Memory、Sub-agent、Vision Assistant、Commit Description、Worktree Naming、Branch Summary）统一使用上下堆叠的加宽行（`.set-row.wide`，控件占整行宽），模型按钮完整显示选中的模型 ID，不使用省略号截断（放不下时按钮自适应换行）；弹层选项同样完整展示模型与 Provider 名称。第一项“使用主模型”会清空该项的 Provider、Model 和 Effort，运行时连同主模型当前的 Thinking Effort 一起继承；选了具体模型且它有多个档位时，旁边出现 Effort 按钮，打开同一种滑杆，下面多一个“默认”，表示不覆盖、不发送 Effort（规则见 [settings.md](settings.md)）。

  **Providers 页**是左右两栏：左边是 Provider 列表（状态点：可用 / 缺少 Key / 已停用）和 “Add provider”，右边是选中 Provider 的编辑区。切换 Provider 时如果表单有未保存的改动会先确认。编辑区顶部是名称、ID、状态和启用开关；自定义 Provider 下面是表单，内置 Provider 只显示只读信息和 Key。**打开页面、切换 Provider、重新打开设置、刷新、编辑和保存都不会联系 Provider**，只读本地的 `models.json` 和凭据；没有“刷新全部模型”，旧的 `POST /api/providers/refresh-models` 和 `GET /api/models?refresh=1` 已移除。

  **API Key**：主页面只显示正在使用的 Key 和“管理 API Key”（没有 Key 时是“添加 API Key”）。管理子页面列出全部 Key，可以添加（可选名称；第一个 Key 立即启用，之后的需点“使用这个 Key”）、切换、改名和“删除 API Key”；删除正在使用的 Key 时要选一个替代 Key。OAuth 登录也在这里。“删除 API Key”只删一个 Key，与底部的“删除 Provider”不同；旧的 “Remove credentials”（一次删除全部凭据）入口已去掉。

  **自定义 Provider 表单**：连接卡片（名称、ID、API 格式、Base URL、认证）。**认证**始终提供两种方式，选哪一种都不会让另一种消失：“API Key”（存入凭据库而不是 `models.json`；填好保存后这一栏就地换成已存 Key 的显示，只有名称和后四位，浏览器拿不到明文，状态点也立刻变成可用；同名再保存就是更新那把 Key，不会报“已存在同名 Key”；只含空白的 Key 会被拒绝并提示，不会静默保存成没有 Key）和“在 models.json 中设置”（继续使用 `models.json` 里的 `apiKey`，界面只提示“Key 在 models.json 中设置（已隐藏）”，不显示也不改动它；文件里还没有 Key 时提示到 JSON 视图添加）。选择保存为 `models.json` 的 `authMode`（`apiKey` / `config`），重新打开时按它恢复；没有 `authMode` 的旧条目在文件里有 `apiKey` 时视为“在 models.json 中设置”。没有“无需认证”选项。**Base URL** 输入框为空时只用很浅的灰色显示示例 `https://api.example.com/v1`，示例不是值：新建 Provider 的 Base URL 为空，示例地址本身也不会被当作有效地址保存。**保活时间**（秒，1–600，留空用默认值 120，占位符显示默认值）和 **IP 协议**（自动 / 只用 IPv4 / 只用 IPv6，当前默认项后标“（默认）”，默认只用 IPv4）在 Base URL 下面，各 Provider 单独保存到 `models.json` 的 `keepAliveSeconds` / `ipFamily`；字段缺失表示用默认值，明确选择任一项（包括“自动”）都会写入；非法数字在输入框下标红提示并拒绝保存。默认值由服务端在 `GET /api/providers/custom` 的 `connectionDefaults` 里给出，界面不写死。Base URL 没填时仍可保存，但 Provider 不可用：状态显示“缺少 Base URL”，启用开关不可操作（`POST /api/providers/enabled` 返回 409），它的模型不出现在模型列表里；把已启用 Provider 的 Base URL 清空再保存同样允许，保存后提示“Base URL 未填写，Provider 已停用”。补上 Base URL 并保存后即恢复，不需要其他操作。连接卡片之后是与模型卡片（ID、显示名、是否支持推理、可用 Thinking Effort、图片输入、上下文窗口、最大输出；上下文窗口和最大输出以 K 为单位填写，1K = 1000 Token，输入框里固定显示 “K”，下方显示换算后的准确 Token 数，保存到 `models.json` 的仍是真实 Token 数，例如 128000 显示为 `128`，131072 显示为 `131.072`，最多三位小数）。模型卡片默认折叠成一行摘要，点开才编辑；“Add manually”手动添加。底部固定一栏放“删除 Provider”、放弃和保存。“以 JSON 编辑（高级）”是可选的底层编辑入口，与表单共用同一份数据。

  **模型计价**：模型卡片包含“自定义计价”：输入、输出、缓存命中、缓存写入单价，每个基础和阶梯价格标签随币种显示 `($/1M)` 或 `(¥/1M)`，与 Token 阈值输入区别；添加阶梯使用带加号的次级按钮。支持美元或人民币，以及可选的长上下文阶梯。阈值按每次请求的输入与缓存 Token 总量判断，超过阈值时整个请求使用该阶梯；不是把整个 Session 累计 Token 套入阶梯。Session 费用按当前保存的模型规则计算，币种分别显示（`$` / `¥`），不做汇率转换。Provider 报告用量时随 SSE 实时更新；只在请求末尾报告 Token 的 Provider 无法提供准确的生成中费用。详见 [models.md](models.md)。

  **检测模型**：只有点“检测”才会联系 Provider，而且只检测输入框里写的 Model ID（逗号、空格或换行分隔）。`POST /api/providers/custom/detect` 必须带 `modelIds`，用表单**当前**的连接信息（包括刚输入但未保存的 Key）先读一次模型列表（免费；按 API 格式走各自的列表接口：OpenAI 兼容 `/models`、Anthropic/Mistral `/v1/models`、Gemini `/v1beta/models`），只取这些 ID 在列表里明确写出的能力。检测不会向模型本身发任何请求，也不测试 Thinking Effort：档位、上下文窗口、最大输出等参数，列表和官方文档没写的就由你自己勾选或填写（规则见 [models.md](models.md) 的 Thinking Effort 一节）。检测只针对填写的 Model ID 本身：不查预置模型表、不按名称猜测，ID 不在列表里或列表读取失败时照样返回一个按默认值的模型；没有 Model ID 就不检测。新 ID 会加入表单；已有模型只更新列表能确认的字段（图片输入、上下文、最大输出、目录或官方文档给出的档位），其余保持不变；没写的模型完全不动。列表里没有的 ID 仍会加入并提示检查拼写；列表读取失败会给出具体原因（认证失败、Base URL/路径不对或端点不提供列表、网络错误、上游 5xx、响应格式不对），此时仍会返回按默认值的模型。检测结果要点“保存”才写入 `models.json`。

  保存前删掉某条模型时，结果提示跟着列表走：`provider-models.js` 的 `detectRecord` 按模型条目的 `uid` 记住本次检测新增和更新了哪些条目，`detectOutcome` 每次渲染都用当前列表重算，所以被删条目占的那部分统计和点名它的警告（列表中没有、Effort 无法确认）一起消失；本次检测产生过的条目全部被删去时提示卡片整个撤销，模型列表为空时恢复“还没有模型”的空状态文案。检测失败的提示讲的是请求本身，不随列表变化。

  **删除 Provider**与启停不同：确认后移除 `models.json` 条目、该 Provider 的全部 API Key/登录、指向它的设置（默认模型等）以及备份文件里的对应条目；任何一步失败会回滚 `models.json`。最后一个 Provider 也可以删除，之后 MyHarness 进入“暂无可用模型”的空状态。如果有 Chat 正在用这个 Provider 的模型运行，先弹出选择：“不删除”什么都不改；“立即删除”会立刻停止这些任务再删除（`GET /api/providers/custom/usage` 查询，`POST /api/providers/custom/delete` 需带 `stopRunning: true`，否则只返回运行中的任务列表）。
* **命令面板**（默认 `Ctrl+Alt+K`）：动作、斜杠命令、Chat、文件的统一搜索；↑/↓ 选择，Enter 执行，Esc 关闭。
* **搜索排序**：命令、设置项、Workspace、Chat 和模型的候选都用同一条规则（`web/js/search.js` 的 `rankSearch`），不区分大小写：先按相关性（名称完全匹配 > 名称前缀 > 名称包含 > 说明/关键词匹配 > 字母顺序模糊匹配），同一相关性内再按使用次数，最后保持原有顺序。例如搜索 `git`，`Git` 排在 `GitHub Connect` 前面。搜索框为空时保持原来的按使用次数排序。斜杠命令和 `/settings` 行的使用次数（`usageRanking`，由 `POST /api/commands/usage`、`POST /api/settings/usage` 记录）；模型搜索只按相关性。
* **行内命令面板**：在 Composer 输入 `/settings`、`/model`、`/effort`、`/git`、`/restore`、`/undo`、`/workspace` 并回车，会在输入框上方展开一个类似 CLI 菜单的多级面板（不是设置页）。面板是居中的紧凑卡片，宽度按内容决定：滑杆和只有几项的短选择用小卡片（`sm`/`md`），选项很多（超过 6 项）、带详情（待丢弃的文件列表等）或自定义内容的层级才加宽（`lg`），同一个面板里往返不同层级时尺寸平滑过渡；关闭时淡出。操作：↑/↓/PgUp/PgDn/Home/End 移动，Enter 或 → 进入/确认，Space 切换开关，←/Backspace/Esc 返回上一级（有筛选时先清筛选），可键入筛选；鼠标可选。`/settings` 的行、名称、说明、固定选项和顺序只在 `src/startup/settings-menu.ts` 的 `SETTINGS_MENU` 里定义一次，Web 通过 `GET /api/settings` 的 `menu` 拿到同一份（已按使用次数排序），所以增删、改名、调整顺序或选项只改这一处。Web 独有的行用 `surfaces` 标出（Appearance、Project trust、Auto-retry、Model cycling scope、Web UI exit delay (seconds)、Shell path、Command prefix、Analytics、About）。Web 端只声明每一行怎么打开：编辑单个设置的行由 `routes-settings.ts` 的 `SETTINGS_MENU_SETTING` 对应到设置项，自带页面的行由 `web/js/settings-menu.js` 的 `SETTINGS_MENU_PAGES` 列出，`test/web-frontend-logic.test.ts` 检查两者合起来与注册表一一对应。名称保持英文原文，说明随界面语言显示；编辑的是同一份 `settings.json` / `models.json` / 凭据。面板里每一行都是单行：图标和名称在左，说明以较弱的颜色跟在名称右侧（过长截断），当前值、开关或箭头在最右。Thinking level 和各模型设置项里的 Effort 用与 Composer 相同的横向滑杆（←/→ 调整，Enter 返回）。点击面板以外的任何地方会关闭整个面板（包括多级子页面），面板内的点击和它打开的确认框/菜单不会关闭它；关闭不会清空输入框里的草稿。`/git` 覆盖 Commit、Push、撤销任务、恢复到最新提交、Worktree、历史、仓库登记。一次性命令（如 `/new`、`/compact`）仍直接执行，候选列表与搜索保留。

  **`/commit` 和 `/push` 与终端一致：不需要选择，回车就直接运行**（`/git` 面板里的 Commit / Push 行和 Changes 面板的 Commit / Push 按钮走同一条路径，`web/js/git-flow.js`，仍然是原有的服务端用例，只多了下面说的按文件过滤）。运行中，正文会话流中的状态卡显示一行紧凑的进度（旋转环、服务端报告的阶段文字、Cancel）；结束后正文中的结果卡显示真实结果：成功是 `Commit succeeded` / `Push succeeded`（简体中文：`Commit 成功` / `Push 成功`）加真实的短 hash 和一句说明，失败是失败标题加 Git 给出的真实原因（跳过 `warning:` / `hint:` 这类只是提示的行），`Details` 展开完整输出，成功 Commit 详情里的 `(+X/-Y)` 使用与文件列表相同的新增绿、删除红高亮，其他输出保持原样。Commit 先读取当前仓库全部待提交改动（包含多个对话留下的改动，排除 checkpoint 标记的内部路径）；从 Changes 面板的 `Current conversation` 页签进入时只读取最后一次改动属于本对话的那批文件（`POST /api/git/commit` 带 `{ scope: "session" }`，由 `GitCommitUseCase` 的 `only` 过滤在工作区清单里取交集，描述、hooks 与自动修复流程不变），以相对 HEAD 的真实 Diff 和新文件内容为依据，参考最近 10 条 Git 提交历史的语言和风格，通过当前主模型的独立无工具请求生成标题及按功能分组的详细正文；不依赖当前聊天背景，不添加 AI 署名或 Co-Authored-By 等作者尾注，保留正常 Git 作者身份。取消固定 300 KiB 总 Diff 限制：根据当前模型的 contextWindow 和输出预算分批处理，未知容量按 16,384 Token 窗口保守分批，估算输入预算为窗口的 65% 减输出预算和 1,024 Token 余量；Token 是近似估算，不保证任意 Provider 的实际分词。小改动直接生成；大改动按文件/变更块拆分，优先邻接同名实现与测试和可解析的相对引用文件。每批附整体清单（过大时使用模块计数及清单摘要），保留稳定 Diff ID、文件路径和片段范围。程序校验每批覆盖与来源引用，摘要过大时逐层合并并保留全部原始来源；汇总模型可请求原始 Diff ID 补读核对，最多两轮补读。界面显示批次分析及汇总阶段。没有任意总大小承诺：极大文件仍受内存、Git/Provider 限制，来源列表无法装入单请求或摘要无法收敛时明确失败，不截断源码或忽略未处理批次。任何批次/生成失败、取消或生成期间仓库改变时停止，不悄悄退化为文件清单或提交不完整说明。生成成功后正常执行 hooks。仅当失败输出明确报告 pre-commit hook 失败（支持 Husky 的 script/hook failed 标记及 pre-commit hook failed 标记）时，启动 Agent 修复（最多 3 轮），只处理检查报告的代码问题，禁止弱化检查、改 Git 配置或自行提交/推送。每轮修复成功后重新读取全部 Diff、生成提交说明，并带正常 hooks 重试提交；第 3 轮修复后仍失败则停止，报告已达到 3 轮上限并保留最后一次错误。修复失败或取消立即停止。不把超时、取消、启动失败、身份/锁等其他 Git 错误当作代码问题；无法明确识别的自定义 hook 失败也停止并保留诊断。没有 hook 的仓库不会触发自动修复，不绕过检查、不自动推送。Details 保留完整 stdout/stderr。Push 的 CI 失败仍保留 “Ask the agent to fix CI” 手动入口。进度与结果直接显示在正文会话流中，不再在输入框上方自动消失。每次操作的结果沿用原状态条的配色、图标、hash 和 Details，作为独立记录保存到 Session 的现有 custom entry（`web-git-status`），不进入模型上下文；即使新 Chat 只有操作卡片而没有模型回复，也立即落盘并保留在侧栏，不作为空 Chat 复用；后续操作不会覆盖它，刷新页面或重新打开 Chat 后仍能看到。Changes 的更多按钮在按钮下方、右侧栏内部展开同一个 Git 命令面板。

  需要选择的命令用键盘可操作的行内面板，默认项是安全的：`/undo` 的第一项是 “Keep changes”，撤销要再确认一次；`/restore` 先列出将被丢弃的文件，第一项是 Cancel，之后才是 “Discard and restore”；它们的结果同样作为独立卡片保留在正文会话流中。`/undo` 需要存在任务检查点，而检查点只在开启 Git integration 时创建；没有检查点时面板说明原因，并指向 “Restore to last commit”。撤销的确认框会先列出“这次回滚会连带覆盖的其他对话文件”（检查点之后由其他会话直接改过、或落在其他会话命令时间窗内的文件，`GET /api/git/undo/preview`，最多列出 40 个并给出总数），回滚范围本身不变。`/workspace` 同样是多级面板：Workspace 与 No Folder → 其中的 Chat（打开）/新建 Chat/从列表移除，以及添加 Workspace。
* **斜杠命令的来源**：内置命令只在 `src/startup/slash-commands.ts` 的注册表里定义一次（名称、别名、说明），Web 的 `/api/resources`（`resources.commands`，含 `aliases`）读它，Web 前端不再有自己的一份命令表。斜杠命令不会打开右侧面板；`/setting` 是 `/settings` 的别名。`web/js/builtin-commands.js` 只声明每个命令在浏览器里怎么执行（`panel` 打开行内面板、`action` 立即执行、`prompt` 作为消息发给 Agent），`test/web-frontend-logic.test.ts` 检查它与注册表一一对应。
* **键盘操作**：行内命令面板的列表超过 4 行时默认带筛选框（设置根层也会搜索每一个具体设置项，例如输入 `exit delay`），进入子层时焦点和选中项稳定，返回上一层时恢复筛选文字与选中项；`Tab`/`Shift+Tab` 循环，`Space` 只在筛选框为空时切换开关，不劫持输入框。命令面板（`Ctrl+K`）和 Composer 的候选用键盘选择时，鼠标停在原位不会抢走选中项（只有鼠标真的移动才会）。需要审批/选择的对话可以直接用键盘回答：←/→/↑/↓/Tab 选择，Enter 确认，Esc 拒绝或取消，选项对话可按 1–9，`Alt+A` 把键盘焦点拉回该对话。
* **斜杠命令候选**：只有 `/` 是消息的第一个字符时才出现（正文、路径或 URL 中间的 `/` 不触发），输入 `/` 立即展开，继续输入实时筛选；中文输入法下 `/` 键打出的全角 `／` 或 `、` 作为第一个字符时按 `/` 处理。输入 `/c` 等内容时候选列表高亮一个命令：`Enter` 直接确认并执行它（多级命令如 `/settings`、`/workspace` 立即打开对应面板，`/compact` 等立即执行），`Tab` 只把命令名补进输入框以便继续写参数，`↑/↓` 换选（从第一项按 ↑ 跳到最后一项、从最后一项按 ↓ 跳回第一项，列表会跟着滚动，选中项始终可见；行内命令面板同样如此），鼠标点选等同 `Enter`。`Esc` 或点击输入卡以外的地方只关闭候选列表，不改动草稿；继续输入会重新出现，删掉后再输入 `/` 也会重新出现。`@` 文件候选没有“执行”，`Enter`/`Tab` 都是插入。

### 界面语言

设置 → 外观 → **界面语言**（或命令面板里的 Language 项）在 English 与简体中文之间切换，立即生效并保存在浏览器；默认 English。只翻译 MyHarness 自己的界面文字（菜单、按钮、状态、设置、提示、空状态、错误、运行状态），不翻译用户与 Agent 的消息、代码、文件内容和命令输出。开发者术语保持英文：Terminal、Session、Workspace、Provider、Commit、Push、Diff、Worktree、Thinking Effort（及 off / minimal / low / medium / high / xhigh / max 等档位名）、Markdown、JSON、PowerShell、Bash、Git 和路径等，只翻译它们周围的句子，中英文之间留空格（`test/web-i18n.test.ts` 检查）。

* 机制：`web/js/i18n.js` 以英文原文为 key（`t()` / `N_()` / `tNodes()` / `count()`），中文词典只放在 `web/js/locales/zh-CN.js`；右侧栏内置工具的中文描述按工具名放在 `web/js/locales/zh-CN-tools.js`，新增内置工具时要补条目（测试会检查）；MCP/扩展工具保持英文。源码里其他位置不出现中文（测试强制）。
* 服务端产生的文本：设置项、错误等英文文本由词典翻译；终端侧固定为中文的文本（运行状态、Git 阶段、命令说明等）通过 `serverTextEn` 在英文模式下映射为英文，未知的中文不会显示在英文界面里。CLI 的输出不变。
* 新增界面文字：用 `t("English text")` 并在 `zh-CN.js` 补条目；`test/web-i18n.test.ts` 会检查缺失的翻译、占位符不一致和源码里的中文。

### 与另一个 Web 进程共享同一个会话

一个 Session 同一时间只有一个进程运行它的 Agent 并写它的 JSONL（持有写入锁的 **owner**）。以前在 Web UI 里切换到另一个进程正在运行的会话会报 `Session is already active in another MyHarness process`；现在 Web 进程（`setMirrorSessionsAllowed(true)`，在 `startWebBootstrap` 里打开）发现会话被另一个活着的进程占用时，会**附着**到它。谁先打开谁是 owner，另一方是附着方：

* owner 在持有写入锁期间，在回环地址上开一个小服务（`agent/runtime/session-bridge.ts`），端口和随机令牌写在会话旁的 `<session>.jsonl.bridge`（`session/bridge/descriptor.ts`，只含 pid / 端口 / 令牌，不含会话内容；owner 释放锁时删除）。服务把 owner 的每个 `AgentSessionEvent` 连同当时的运行状态（是否在运行、排队消息、模型、后台任务数等）推给附着的进程（流式更新合并为每 40 毫秒一次），并接收 `prompt / steer / followUp / abort / clearQueue / setModel / setThinkingLevel` 命令。
* 附着的一方是 `MirrorAgentSession`（`agent/runtime/mirror-agent-session.ts`）：它是一个普通的 `AgentSession`，读取类能力（消息、模型、上下文用量、设置）照常工作，但 Agent 不在本进程运行。会话 JSONL 由 `SessionManager.syncFromDisk()` 只读取 owner 新追加的字节来跟随；owner 的事件原样回放给本地订阅者，所以 WebHost、前端的对话流、工具输出、运行状态、速度与缓存命中都和 owner 端同步。在 Web 里提交输入等于向这个会话提交任务，由 owner 照常执行；两端看到同一份对话。附着方不写会话文件，不做完成阶段的 Git checkpoint / Auto Memory / 系统弹窗（这些由 owner 做），`snapshot.flags.mirror` 为 `true`。
* 同进程通过 junction/symlink 等目录别名打开同一会话时，写锁按真实目录路径共享本地租约，不把第二个 runtime 当成其他进程。锁 owner 标记存在时，bridge 的 PID 必须与它一致才能尝试附着，之后还需通过 bridge 令牌握手；残留 bridge 不能单独证明会话在其他进程运行。明确已退出的 owner 的锁按原有安全校验恢复，未知锁仍保留 stale 等待，不强制删除活进程的锁。Web 协同提示是可手动关闭、也会自动消失的通知，不是阻塞弹窗；不提供强抢活进程写锁的操作。
* owner 进程结束（或关闭该会话）时，附着方收到断开，接手该会话（owner 释放写入锁需要一瞬间，期间重试，最多 15 秒），此后它就是 owner：Web 由 `WebHostHub.reclaimMirror` 在同一个 slot 里重新打开。没有开启附着的 headless SDK/worker 遇到被占用的会话仍然报原来的错误。

### 同时运行多个会话

多个 Chat 可以同时运行，互不影响：每个打开的 Chat 是服务端 `WebHostHub`（`hub.ts`）里的一个 slot，拥有独立的 `AgentSessionRuntime`（session、cwd 绑定的服务、Git checkpoint、对话框队列、消息与工具流）。请求通过 `x-myharness-slot` 头（或 `slot` 查询参数）定位 slot（浏览器自己加载的地址，如 PDF、媒体、下载、Office 预览，带不了请求头，由 `store.js` 的 `slotUrl()` 补上 `slot` 参数，否则相对路径会按主 slot 的文件夹解析），SSE 事件带 `slot` 字段，前端 `store.js` 为每个 slot 保存独立状态并只渲染当前 slot。切换 Chat 只是换显示哪个 slot，后台 Chat 继续运行，回来时看到的是真实状态；侧栏用 `slots` 事件显示每个 Chat 的运行/等待/结果。空闲后台 slot 按最近使用顺序和约 256 MiB 的估算内存预算保留，另设 16 个硬上限（`MAX_IDLE_BACKGROUND_SLOTS`）；估算不是进程真实堆占用，不限制运行任务。当前、主 slot、运行中、收尾、Git 操作、等待回答或有未读结果的 slot 不释放；已释放的 slot 再请求会返回 410，前端自动重新打开。

### 运行控制

Agent 正在运行时发送消息有三种行为，直接映射 MyHarness 真实的机制。Composer 上没有发送方式菜单：Enter 和发送按钮用哪一种，在设置 → 外观 → 对话 → **While a task is running**（或行内 `/settings` 的 Appearance）里选，保存在浏览器，默认 Steer；输入框的占位文字、发送按钮的提示和 About 里的快捷键说明都会写出当前选择的行为。`Alt+Enter` 始终是 Queue。

| 行为 | 怎么触发 | 效果 | 底层 |
| --- | --- | --- | --- |
| **Steer** | 设置里选它（默认）后按 Enter / 发送 | 在当前运行的下一个模型步骤前送达，不会打断正在执行的工具 | `AgentSession.prompt(..., { streamingBehavior: "steer" })` |
| **Queue** | `Alt+Enter`，或设置里选它后按 Enter / 发送 | 等当前运行完全结束后再送达 | `streamingBehavior: "followUp"` |
| **Interrupt** | 设置里选它后按 Enter / 发送 | 立即中止主 Agent 当前这一轮，然后发送新消息。正在运行的子智能体（`agent` 的前台/后台批次、workflow、ultracode）**不会被取消**：前台派发转入后台继续，结果回来后交给主 Agent 并触发综合（结果在新消息的回答进行中到达时，排到这一轮结束后）。主 Agent 已答完、任务只在等后台子智能体时没有运行可中止，改按 Steer 送达 | `AgentSession.abort({ keepBackground: true })` → `waitForForegroundIdle()` → `prompt()`（等子智能体时：`streamingBehavior: "steer"`，由 `WebHost.submit` 用 `isWaitingForBackground` 判断） |
| **Stop** | 停止按钮，或输入框为空时按 Esc | 中止当前运行**和全部子智能体**（运行中提示为“停止本次运行和全部子智能体”） | `AgentSession.abort()` |

排队中的消息显示在 Composer 上方，可一键放回输入框。运行中发送的消息（steer / 运行结束后）不会先作为乐观行画进聊天区，而是立即以本地 `outbox` 条目显示在这个队列里，等服务端 `queue_update` 列出它、或它真正投递（`message_start` 带同一 clientMessageId）时再由服务端状态接管；`verifyLiveUpdates` 对这类消息以"已进服务端队列或已落地"为准，不再每次发送都重建事件流并重读 transcript。

### 子智能体活动条

子智能体（`agent` 工具的前台和后台批次、workflow、ultracode）在运行时只在一个地方实时显示：输入卡上方的活动条（`web/js/sub-agents.js` 的 `SubAgentBar`，与运行状态条同一层，不挤占 Workspace / 分支 / 模型标签）。正文里不再有派发卡片：派发它的那一步仍是紧凑的工具行（“正在委派 / 已委派…”），下面是“已完成 n/m 个任务 · 模型”和每个任务一行（状态点、任务名、工具调用数、耗时），运行中随进度更新；历史 Chat、后台运行和被打断的轮次都是这一种显示。

* **三层展开**：活动条 → 某一个子智能体 → 它的一次工具调用。每层各自点开、各自收起，点开一层不会顺带展开下一层，全部在活动条内部发生，不滚动正文、不跳转。
  * 第一层是活动条的标题行：“N 个子智能体运行中 · 已用 X 分 Y 秒”，计时从仍在运行的最早一次派发开始；有派发在后台运行时，标题文字右侧紧跟一个“后台”徒标（小图标 + 文字，样式与其它 .badge 相同）。活动条出现时默认展开，点一下标题行收起、再点展开；展开后一次列出全部子智能体（已结束的也在），没有“显示更多”。
  * 清单按派发分组：每组直接列出每个子智能体一行——状态、任务名、当前动作或结束方式（沿用工具行的文案，如“已读取 src/m1.js”“已从面板停止”）、它自己的工具调用次数和计时、折叠箭头；没有单独的派发头行，派发是什么（workflow「名称」还是 N 个子智能体）、模型是什么，看正文里的派发行和展开后的过程头。workflow / ultracode 在组内按“阶段 → 任务”两级显示（阶段头带阶段名和完成数），不为层级另加下钻。
  * 第二层：点子智能体那一行（除停止图标外任何位置）在行下展开它的过程：模型和派发标识，它按顺序做过的工具调用，然后是它的报告（错误、正文、发现、未解决）。工具调用行直接复用主智能体的工具行（`describeAction`、`StatusGlyph`、同样的文案、耗时和折叠箭头），同一种工具永远是同一种样子；失败用错态样式，子智能体结束时仍标着运行中的调用显示“未完成”。
  * 第三层：点过程里的某一行工具调用，展开这次调用的参数和结果摘要（失败时为错误摘要和错误类型），到此为止。
  * 数据来源：服务端只为每个子智能体记录工具调用轨迹（`transcript`：工具名、参数、状态、耗时、结果摘要），不记录它的思考文本，所以过程里没有推理步骤。活动条的轻量状态（`sub_agent_state`）不带轨迹；过程取自 `sub_agent_progress` 的完整 details，没有时（例如运行中刷新了页面、还没收到新进度）展开显示“暂无过程”，照样可以展开，不编造步骤。
  * 滚动：活动条的清单是唯一的滚动区（`.sa-list`，最高 `min(42vh, 360px)`，不会顶掉输入框），第二、三层不再各自出现滚动条（这里的 `.raw-body` 取消自己的高度上限）。正文工具行展开卡片“一个滚动区”的规则（`test/web-tool-expand-layout.test.ts`）在正文里不变；正文派发行展开时，任务详情框 `.sub-detail` 是那里的唯一滚动区。
* **全屏**：标题行右侧的全屏图标（`maximize`）把同一份清单放大到一个大浮层（`min(1100px, 100vw − 48px)` 宽，复用 `ui.js` 的 `Modal` / `Overlay`），展开到哪一层、放大后还是哪一层，退出后也保持；浮层右上角是退出全屏图标（`minimize`），Esc、点浮层外部同样退出，Esc 只关浮层、不停止运行；退出后焦点回到全屏图标。浮层里只有浮层正文一个滚动区。
* **结束提示**：最后一个子智能体结束后，活动条收起成一行“全部完成 / N 个失败 / N 个已停止”，约 6 秒后消失；点它在活动条内展开或收起刚结束的清单（不跳转），展开期间或全屏期间不消失，收起后再过约 6 秒消失。
* **整行可点与键盘**：鼠标点行内除图标按钮外的任何位置都切换展开；每行的主体是一个真正的按钮（带 `aria-expanded`），Tab 可以聚焦，Enter / Space 切换；停止和全屏图标是单独的按钮，可以单独聚焦和触发，它们的点击和按键不会传到整行。
* **停止**：界面只有一处停止入口——标题行（及全屏的同一行）的“停止全部子智能体”，方框图标（播放器的“停止”），灰色、无边框，悬停或键盘聚焦时才变亮，发送 `{ all: true }`；子智能体行上没有单停按钮。它只停止子智能体，不停止主 Agent 的当前这一轮；输入框的停止按钮才停止全部。接口是 `POST /api/sub-agents/stop`（`routes-core.ts`），仍接受 `{ id }` / `{ id, phase?, task? }` 这种更细的目标（保留给其它客户端与测试），界面只用 `{ all: true }`；停止会等子智能体确认结束（最长约 15 秒），请求期间图标换成转圈；什么都没停下返回 409，有子智能体没确认返回 500，前端都以错误提示（含服务端原因）显示，不会显示成已停止。停止不是删除：已产出的内容保留在步骤里，但**不会自动交给主 Agent、也不触发综合**；主 Agent 需要时用 `agent_tasks` 的 `list` 读取。主 Agent 正在等的子智能体被全部停止时，任务直接回到空闲，不跑综合轮。前台派发被整批停止时，返回给主 Agent 的结果会注明“用户从面板停止，不要自动重派”。
* **被打断与后台**：有派发在后台继续运行时（前台派发被打断，或 `run_in_background`），标题行在“N 个子智能体运行中”右侧标“后台”，不再区分“已转入后台”；正文工具行仍按自己的口径显示“在后台运行”。被打断/失败的那一轮的结果横幅里显示“后台仍有 N 个子智能体在运行”，点击只展开活动条，不滚动正文。主 Agent 已答完、只在等子智能体时，运行摘要显示“等待 N 个子智能体 · 已用 …”。
* **状态**：运行中（转圈）、完成（中性色对勾图标）、部分完成（警告色三角图标）、失败/超时（危险色圆形感叹图标）、已停止/已取消（灰色停止图标，不转圈；行内写明“已从面板停止 / 已由主智能体停止 / 已随任务停止”），重连期间为“状态未知”（时钟图标，没有停止入口）。
* **主 Agent 的控制**：`agent_tasks` 工具（`src/tools/agent-tasks.ts`）可以 `list` 本对话的派发、任务编号、状态和当前动作，也可以 `stop` 一个、多个（`<id>`、`<id>#<任务>`、`<id>#<阶段>.<任务>`）或全部，返回被停止任务已经产出的内容。关闭子智能体时它和 `agent` 一起从工具列表中移除。
* **状态真实性**：状态由服务端 `sub_agent_state` 事件（约 200ms 节流）和快照里的 `subAgents` 提供，只描述当前进程里的派发，不回放历史。断线重连期间显示“状态未知”而不是“运行中”；刷新或切换 Chat 后按服务端快照恢复；服务重启或 Session 释放会真正停止所有子智能体（含其工作进程），重启后旧的派发不会显示为运行中。

### 状态语义

“轮次结束”不等于“任务成功”。摘要与横幅使用明确的状态：`Completed`、`Partially completed`（失败/超时但已改动文件）、`Failed`、`Cancelled`、`Waiting for you`。运行中的状态来自 `RunStateSnapshot`；结束后的状态来自 `run_state_changed` 的终态；历史消息（没有运行记录）按最后一条 assistant message 的 `stopReason` 推导，并且只声明能证明的事实（例如“No file edits were recorded”而不是“没有改文件”）。

状态提示全站只用两档强调（`web/css/` 各组件规则内实现，`tokens.css` 不变）：默认只给图标和标题文字上前景语义色，底色和边框保持中性；只有需要你立刻处理的异常（记忆维护需要处理、Git 操作失败、没有可用模型、与本地服务断连）才再加 `--*-soft` 淡底。已完成、已取消、等待你的回复、进行中一律是中性色。同一状态在正文结果卡、顶栏状态胶囊、侧栏模式开关标记、子智能体列表和 toast 里用同一个图标（完成 `checkCircle`、部分完成和没有响应 `alertTriangle`、失败 `alertCircle`、取消 `stopCircle`、等待 `clock`）和同一档颜色。结果卡不再是带底色和边框的浮板，而是轮次里一条左侧中性竖线引导的区块。失败文字（例如“模型请求失败：原因。建议。\n原始信息：……”）默认只显示第一句，卡片标题行右侧的“详情”按钮（`aria-expanded`，可用键盘操作）展开其余全部内容，再点“收起详情”折回；拆分只按句号/换行切开显示，不删除任何文字（`web/js/util.js` 的 `splitFirstSentence`）。

### 审批与用户问题

MyHarness 核心没有内置的工具权限系统；审批来自 Extension 通过 `ctx.ui.select/confirm/input/editor` 提出的问题（例如 `examples/extensions/permission-gate.ts`）。Web UI 实现了同一套 `ExtensionUIContext` 对话方法（`mode: "web"`）：问题显示在 Composer 上方的操作条里，不是 Modal，头部同时显示 `Waiting for you`。操作条表达的是“等你选择”而不是出错：中性边框、时钟图标，不用警告色；键盘焦点在操作条里时边框变成焦点色。选择题的选项每行一个、左对齐、与卡片同宽，长短文案对齐方式一致；快捷键说明保留在原位，平时用最淡的文字色，悬停或聚焦时加深；有 timeout 的对话会倒计时。Project Trust 问题（启动或切换到其他项目时）在浏览器里回答。

## 与 CLI 的关系

* Web 服务里每个打开的 Chat 各有一个 `AgentSession`，可同时运行；每个都走相同的完成阶段与 Git checkpoint。切换 Chat 不会中断运行中的任务。
* 完成阶段沿用同一批函数：`collectFinalWorkspaceChanges`、Git checkpoint 的 complete / retain、Auto Memory 提取、`agent_response_ready` 事件。
* Git：`/commit`（`GitCommitUseCase`）、`/push`（`GitPushUseCase`）、`/restore`（`discardChangesToHead`）、`/undo`（`restoreGitCheckpoint`）、Worktree（`GitWorktreeUseCase`）、本地仓库登记（`LocalGitRepositoryStore`）都调用现有用例，没有新的 Git 逻辑。
* Settings 通过 `SettingsManager` 写入同一份 `settings.json`；Provider 凭据通过 `ModelRuntime` 写入同一份 `auth.json`。浏览器只会看到密钥的后四位。

与旧终端的已知差异（有意为之，见 [维护](#维护)）：

* `/commit` 仅对明确报告的提交前 hook 失败自动修复并重试，最多 3 轮修复（首次提交加最多 3 次重试）；达到上限仍失败、修复失败或其他错误时停止，在正文结果卡片显示原因（`Details` 保留完整 Git 输出）；`/push` 的 CI 失败保留 “Ask the agent to fix CI” 手动入口。
* 最终回复不会因 Auto Memory 整理而被延迟显示。
* 只有停止按钮（以及服务退出、Session 释放）会让子智能体一起结束：后台批次、workflow、ultracode 被中止，活动条和步骤里的行立刻变成“已取消”（没有转圈）。主任务因失败、超时、出错或被新消息打断而结束时，子智能体继续运行，结果回来后照常交给主 Agent 并触发综合；单任务时限、卡死看门狗和轮次上限不变。
* 主任务**正常完成**时分两种：没有后台 Explore 批次（`agent` 工具的 `run_in_background: true`）在运行，直接结算；还有批次没回来，任务**不结算、也不取消它们**——运行状态保持“进行中”（`waiting`，活动文字“等待子智能体”），批次完成后它的结果以 `background-explore-complete` 消息交给主 Agent，主 Agent 再跑一轮综合，这时才结算（`_emitAgentSettled`）。主 Agent 此时还在连续调用工具（没有停下）时，结果不等它停下：在当前这一轮的工具调用结束后、下一次请求模型之前就送达（作为 steering 消息排队，`AgentSession` 的 `deliverResult`）。多个批次要全部回来；等待期间又启动的新批次也一并等。批次失败、超时或只有部分结果时，结果同样交回。等待前主 Agent 的“已派出，等结果”照常显示，之后会再出现综合后的最终回复。等待期间发新消息沿用运行中发送消息的现有方式（插话、排队、打断），后台批次都不会被取消：此时没有模型运行可打断，所以“打断”按插话送达（`AgentSession.isWaitingForBackground`），主 Agent 回答新消息后继续等；主 Agent 正在回答时的“打断”也只中止这一轮，不取消子智能体；只有停止按钮会让任务和所有子智能体立即取消。等待本身没有额外的时间上限，只受子智能体自己的单任务时限、卡死看门狗和轮次上限约束。前台派发（不带 `run_in_background` 的 `agent`、workflow、ultracode）被打断转入后台后，同样按这套等待、送达和综合规则处理（`background-workflow-complete` 用于 workflow / ultracode）。
* 旧终端专用的 Extension 能力（`custom()` 组件、自定义 editor/footer/header）在 Web 中无效；`setStatus`、`setWidget`（字符串数组）、`setWorkingMessage`、`setTitle`、`notify` 与对话方法有效。
* Terminal 面板的交互式终端只在 Web UI 里有：它是用户自己的 Shell，Agent 的 `bash`/`pwsh` 工具仍然每条命令单独执行，不使用这个终端。
* “这一轮改了什么”的数据只在本次服务进程里记录（最近 12 轮）；重启后历史 Chat 仍能看到步骤，但 Changes → Current conversation 不含旧任务。`Working tree` 范围永远读取真实的 Git 状态。

## 安全

* 只绑定 `127.0.0.1`；校验 `Host`（防 DNS rebinding）、`Sec-Fetch-Site`、`Origin`；所有写请求必须带 `x-myharness-web: 1`；响应带严格 CSP（仅同源脚本，无内联脚本）。
* 文件 API 默认只读，路径解析后必须落在当前 Workspace 内（含符号链接检查）；文件夹选择器只列子目录名。面板内的文本编辑只有 `POST /api/files/text` 一条写路径：只接受 UTF-8 文本（保留 BOM），拒绝二进制/媒体/Office，调用方必须带上读到的原文，与磁盘不一致时返回 409 且不写盘。`GET /api/files/raw` 带 Range 支持（供 PDF 与音视频拖动进度）；文件标签的接口（read/raw/text/markdown 以及分页的 bytes/text-*）对相对路径仍限制在工作区内，绝对路径须是本机文件（拒绝网络/设备路径），因为聊天链接和附件常在工作区之外。其余写路径同样带冲突校验：`POST /api/files/bytes`（原字节+大小）、`POST /api/files/text-segment`（片段原文+大小）。`GET /api/files/site/<token>/…`（HTML 预览）是唯一允许跨站来源的 GET：沙箱页面是不透明源，它加载自己文件夹的资源时浏览器会标为 cross-site；豁免按规范化后的路径判断（`%2e%2e` 之类无法借道到别的接口），且只服务该 token 对应的文件夹、只给非 fetch/XHR 的加载。`POST /api/office/callback/<token>` 是唯一不要求 `x-myharness-web` 头的 POST（文档服务器发不出这个头）：它只认随机的会话 token，设置了 JWT 密钥时还校验请求体 `token` 或 `Authorization: Bearer` 中的 HS256 签名，跨站请求仍被拒绝；嵌入编辑器的 `/api/office/editor` 页面有自己的 CSP（只放行所配置的服务器与带 nonce 的脚本，`frame-ancestors 'self'`）。文档服务器通过浏览器访问 MyHarness 的同一地址读文件和回调，所以它必须能直接访问本机的 MyHarness 端口（同机原生安装或主机网络）。
* 内置浏览器（仅桌面端）：每个标签是一个沙箱化 `WebContentsView`（无 preload、无 Node 集成），共用持久化的 `myharness-third-party` 分区；网页权限默认拒绝，第一次请求在标签内以「本次运行允许 / 拒绝」询问，未回答、切走标签或关闭标签都按拒绝处理，决定只在本次应用运行期间记住，可从工具栏盾牌撤销；Agent 只能触发页面自己的请求，不能代替用户授予权限。下载保存到系统下载目录（自动重名）并上报进度，可按 id 取消或重试；新窗口链接变成工作区标签；新建标签是空白的，只有地址栏，桌面上不会为它创建原生视图，第一次打开地址或搜索时才创建，所以面板保留自己的主题底色而不是一块空白的网页；顶栏的地球按钮打开浏览器时，优先回到这个对话当前正在看的浏览器标签（否则取标签条里最后一个），没有才新开一个空标签，不再固定打开某个站点。`Ctrl+T` / `Ctrl+W` / `Ctrl+F`、查找结果、文件上传（只允许当前工作区内、普通文件、100 MiB 以内的路径）都由桌面宿主执行。Agent 侧同名工具（`workspace`）只能通过应用页面自己的 `contextBridge` 调用，不能作为本地 HTTP 接口使用，也无法绕过上述权限与站点限制。浏览器标签切走时原生视图立即隐藏并由统一布局同步重新计算 bounds，不会覆盖 Session/Terminal/文件/媒体标签。
* 模型输出的 Markdown 不渲染原始 HTML，链接协议白名单，远程图片被 CSP 阻止。
* `models.json` 中的字面量 key / header 在浏览器里显示为占位符，保存时未改动则保留原值。
* Terminal 面板的终端是一个拥有当前用户权限的真实 Shell（与已有的直接运行命令相同的信任边界）。它的接口和其他写请求一样只接受本机同源页面的请求；工作目录由请求所属 Chat 的文件夹决定，页面不能指定；同时运行的终端最多 16 个。

数据流：浏览器 → `POST /api/...`（命令）；服务端 → `GET /api/events`（SSE：`message_*`、`tool_*`、`usage`、`run_state`、`run_finished`、`task_notification`、`queue_update`、`dialogs`、`session_replaced`、`terminal_data`、`terminal_exit` 等）。客户端 `store.js` 用 `/api/state` 与 `/api/transcript` 做快照，断线重连后重新拉取。

`GET /api/transcript` 支持两个可选 query（不带时默认全量，响应与旧版逐字节一致，老客户端、导出和测试依赖这一点）：`limit` 最多返回最近多少条 item（只取尾部，并把窗口起点前移到其中最旧的 user 条目，保证一页不会从 turn 中间开始；非数字/小数回落为不限，`0` 与负数夹到 1）；`before` 是游标——某个 item 的稳定 id（即 Session Entry id，不是时间戳），只返回它之前（不含）的更旧条目，未知 id 宽容忽略。分页响应多出 `hasMore`（更旧处还有条目）与 `nextCursor`（本页最旧 item 的 id，作为下一页的 `before`；`hasMore=false` 时为 `null`）。

终端的数据流：`POST /api/terminal/open`（Shell、列数、行数）返回该文件夹里这个 Shell 的终端——已有就返回它，没有就启动一个——连同它保留的输出（最近约 40 万字符）和一个序号；之后的输出通过 SSE `terminal_data`（带递增序号）到达，页面发现序号不连续或 SSE 重连后会重新取一次。`/api/terminal/input`、`/resize`、`/close` 按终端 id 操作，`GET /api/terminal/shells` 列出可用的 Shell。终端属于服务而不是某个 slot，所以这两个事件不带 `slot`，由 `web-mode.ts` 创建的 `WebTerminals` 直接广播，`store.js` 把它们原样交给正在显示的终端（`onTerminalEvent`），不进入状态。静态资源目录由 `getWebUiDir()`（`config.ts`）解析，源码、dist、Bun binary 三种布局都指向包根/可执行文件旁的 `web/`。

## 维护

* 前端没有构建步骤；改 `web/` 下的文件后刷新页面即可。导出 HTML 时服务端在运行时把前端打包进单个文件，这次打包发生在导出请求的服务端运行时，不属于构建步骤。
* 图标 + 文字的对齐只有一条规则（`css/base.css`）：这类控件都是 `align-items: center` 的 flex 行、固定 `gap`、整数像素行高；图标旁的 `+/-` 行数用 `text-box` 裁到数字本身的高度。Composer 底部的上下文用量（圆环 + 百分比）是和旁边的模型 / Effort 按钮同一种文字控件：同样的高度、字号和行高，所以圆环与其他图标在同一条中线上，百分比与其他文字在同一条基线上。新增同类控件沿用这条规则，不要逐个位置写偏移量。新增第三方前端库必须放进 `web/vendor/` 并更新 `THIRD_PARTY_NOTICES.md`。
* 图标只有一个来源：`web/js/icons.js`。业务代码只用 `<Icon name="…" />` 取图标（下拉箭头用 `ui.js` 的 `Chevron`，也是 `chevronDown` 图标），不写裸 `<svg>`、内联 path、data-uri、CSS 背景图或字符图标；要新图标先找有没有同义的，有就复用，同一功能全界面只有一种图标。
  * 风格：24 网格、无填充、只用文字颜色（`currentColor`）、圆头圆角。大部分图形直接取自 Heroicons 2.2.0 outline 的路径（MIT，声明见 `THIRD_PARTY_NOTICES.md`，许可证原文 `web/vendor/LICENSE.heroicons`；没有引入 npm 包，也没有 vendor 文件）；Heroicons 没有的十来个（侧栏、面板、Git 分支 / 提交、思考、插头、树、图钉、行、魔杖、引用、盾牌）在同一网格上按同样手感自绘。`terminal` 和 `chat` 就是模式开关滑块变形图标的两个终点形状，开关两侧和滑块是同一幅图。
  * 描边：按尺寸分两组，同一尺寸全界面只有一种粗细，由 `icons.js` 的 `strokeFor(size)` 决定，调用方不能再传粗细。14px 及以上是 1.5（Heroicons 原值；16px 时正好 1 个设备像素）；13px 及以下（11–13px）是 1.75。依据：在 1× 屏上逐个比较 11/12/13px 的 1.5、1.75、2.0，1.5 渲染不到 0.9 个像素、看着发虚；2.0 让齿轮、芯片、地球这类复杂图标糊成一团，也比旁边 14px 的图标更重；1.75 在 1× 和 2× 屏上都清楚，粗细与 14–16px 的 1.5 观感一致。
  * 播放器语义，各只有一种图标：三角（`play`）是播放 / 开始，双竖条（Heroicons `pause`）是暂停，方框（`stop`）是停止。输入框的停止按钮、子智能体活动条的停止（一次停全部子智能体）都是同一个 `stop` 方框（也是线框，不填充）；已停止 / 已取消的状态用 `stopCircle`（这是状态，不是操作）。界面目前没有暂停操作，所以图标集里没有暂停图标；以后需要时只能用双竖条。
  * 下拉箭头：`.select` 按钮、自绘 Select 的触发按钮和 Composer 的胶囊都渲染同一个 `Chevron`（12px，颜色 `--text-3`，在 `.select` / `.select-like` 里距右边框内侧 10px、垂直居中，Select 展开时转 180°）。原来四套主题各写一份的 `--chev-img` data-uri 已删除，颜色跟随各主题的 `--text-3`，与原来写死的颜色值相同。
  * 允许保留的三处自绘图形：`ui.js` 的 `Spinner`（转圈）、`mode-switch.js` 配 `mode-icon.js` 的模式变形图标、`context-usage.js` 的上下文用量环。它们不是图标，逻辑不变，只是描边也走 `strokeFor`（用量环画在 20 网格上，用 `strokeFor(16, 20)` 换算成同样的实际粗细）。
* 尺寸、圆角和留白只有一套规范，数值都在 `css/tokens.css`，不要在各处另写数字：
  * 控件高度：带边框的控件（按钮 `.btn`、下拉 `.select`、输入框 `.field`）只有两档——常规 32px（弹窗、表单）和紧凑 28px（加 `.sm`；分段控件、Composer 的模型按钮、面板标签也是这一档），所以放在同一行时高度一致。只有图标的按钮是 32px，放在行内时 24px（`.icon-btn.sm`）。开关只有一种（`ui.js` 的 `Toggle`，`.toggle`）；命令面板的行本身就是可点的控件，行尾用同一个开关的外形（`<span class="toggle on">`）只显示状态。
  * 交互状态（`css/base.css`）：悬停亮一级（有边框的控件边线加深）、按下再深一级、键盘焦点用 `:focus-visible` 的轮廓（输入框显示在边框上）、禁用统一用 `--disabled-opacity`。新控件沿用这几条，不要各写一套。
  * 圆角按角色取 `--r-xs` … `--r-xl`（标记和菜单行、列表行、控件和浮层、卡片和两块主面板、弹窗和输入卡片），胶囊形（徽标、标签、开关）用 `--r-pill`。
  * 留白：侧栏里的行、按钮和搜索框都从 `--pad-side` 开始、到它结束，行尾的图标按钮（收起侧栏、添加工作区、工作区操作）在同一列；工作区下面代替对话列表的文字（提示、“再显示 n 个”）和对话标题左对齐。右侧面板里每一行（标签条、工具栏、Git 栏、文件列表、Diff 标题、各分组）的内容都从 `--pad-panel` 开始、到它结束，行尾的图标按钮向外挂 4px，让图标本身（而不是它看不见的点击区域）落在这条线上。卡片与卡片之间隔 14px：成组的卡片放进 `.stack`。
  * 不写静态的内联样式：间距、对齐、字号都用样式类（`.row`、`.col`、`.stack`、`.grow`、`.pre-wrap`、`.check-label` 等公共类，或该区域自己的类）；只有由数据算出来的值（进度条宽度、树的缩进、浮层位置、弹窗宽度、终端输出的颜色）才写在 `style` 里。
