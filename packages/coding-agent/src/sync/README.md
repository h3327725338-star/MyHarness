# sync/ — Google Drive 同步

## 说明

### 职责

把 MyHarness 中需要跨设备共享的数据同步到用户自己的 Google Drive，并在另一台设备安全合并回来。传输只负责字节；哪些数据属于同步范围、如何合并、删除如何表达，都由本目录的数据适配层决定，不复制整个 Data root，也不把内部状态文件整套覆盖。

### 文件

| 文件 | 内容 |
| --- | --- |
| `types.ts` | 同步协议：实体种类、版本向量、记录、批次、墓碑、冲突、本机状态、状态快照、`DrivePort` 窄接口 |
| `util.ts` | SHA-256、原子 JSON 写、0600 私有写、版本向量比较/合并、稳定 JSON、字节与文本转换 |
| `store.ts` | 本机持久化：`<agentDir>/sync/config.json`、按账号隔离的 `state-<hash>.json`、`credentials.json`（0600）、备份与恢复副本 |
| `scope.ts` | 扫描同步范围：全部记忆（含归档、pending）、通用模式工作区/会话/附件/产物/资料/工具结果、通用个人指令与草稿、Web UI 常用提示词列表（`saved-prompts.ts`，只同步 `web-ui-prefs.json` 里的 `savedPrompts`）、内置浏览器的文件（`browser-data.ts`） |
| `browser-data.ts` | 内置浏览器数据（种类 `browser`）：`<agentDir>/desktop-profile/` 里的书签、新标签页快捷方式、缩放、深色、网站语言、网站权限文件，以及每台电脑一个、由桌面端用同步口令加密的 `browser-vault-<id>.json`；记录 id 与文件名的白名单映射，以及两台电脑同时改动时的对称合并 |
| `apply.ts` | 应用远端内容：记忆写入（memory 锁）、会话 JSONL 按 entry id 合并、文件原子写、工作区身份导入与本机绑定、草稿/指令写入、显式删除 |
| `engine.ts` | 同步引擎：拉取→推送、批次发布、对象上传/校验、版本向量判定、墓碑、冲突保留、活动会话延期、后台定时与文件监听、引擎锁 |
| `google.ts` | Google OAuth（桌面应用 + PKCE + loopback）与 Drive v3 客户端（可见 `MyHarness` 文件夹、`sync-v1` 布局、multipart 上传、媒体下载） |
| `service.ts` | Web 进程内的同步服务：配置、账号切换、OAuth 流程、引擎重建与生命周期 |

### 云端布局

```text
MyHarness/
├─ README.txt
└─ sync-v1/
   ├─ identity.json
   ├─ batches/<batchId>.json
   ├─ objects/<sha256>
   └─ snapshots/<deviceId>.json.gz
```

`batches/` 是只追加的提交日志；每个批次先上传所有对象，再发布清单。`objects/` 按内容哈希去重。删除是批次中的显式操作，附版本向量与删除时间，不靠“这轮没列出”推断。`identity.json` 的 `syncId` 标识同步空间；文件夹改名后仍按 Drive 文件 ID 跟随，不按名字重新建库。`snapshots/<deviceId>.json.gz` 是某台设备已提交的全部记录（gzip JSON：记录、墓碑、64 KB 以内的内容，内联总量最多 32 MB）加 `upTo`（它代表的该设备最新批次时间）；首个成功轮次就写一份，之后本机有比快照更新的批次时重写，最多每 10 分钟一次。某台设备未处理的批次有 20 个及以上时，接收端读它的快照而不逐个读清单，应用后把该设备 `upTo` 以内的批次全部记为已处理。快照只覆盖它自己设备的批次，只是加速手段：批次仍留在云端、仍是事实来源，快照缺失或读不了就照常读批次；快照里的内容超过延期次数仍未到时，本次运行内改读该设备的批次，缺对象按批次报告、可由手动运行重试。

### 本机状态

`<agentDir>/sync/` 不属于 Data root，因此不会被同步本身上传：

- `config.json`：设备 ID/名称、开关、暂停、OAuth client id 与 client secret、云端文件夹与账号标签；
- `state-<account hash>.json`：每个 Google 账号独立的版本向量、墓碑、已应用批次、待绑定工作区、冲突、无法自动解决的问题；
- `credentials.json`：OAuth 令牌，0600 原子写；
- `backups/`、`recovered/`：覆盖前的本机版本与未应用的另一版，按 key 保留最近 20 份。

- `state-*.json.check.json`：仅最近成功检查时间；无协议变化时只原子写这个小文件，恢复时取主状态和此文件中较新的时间。上传与发布日志仍同步原子保存；下载写入远端变更时，状态最多每秒保存一次（轮次结束时再存一次），不再每条变更都整份重写。中途重启时，磁盘上已是来件版本的文件会被直接认领，不重新下载也不算冲突，所以不会丢变更或重复应用。
- 记忆扫描使用异步目录/正文读取及文件签名元数据缓存，未变化的 Markdown 不重复读正文；每次遍历重新检查路径安全，不跨轮缓存祖先检查结果。
- `state-*.json` 的 `publishing`：正在发布的批次日志（先写日志、再写云端清单、再本地提交），中断后下次启动先查云端有没有这个清单，有就直接提交、没有就丢弃重发，不会重复发布。

“待上传队列”就是“磁盘现状与已提交状态的差”：批次成功写入云端后才推进 `entities`/`tombstones`，崩溃后重新扫描会重建同一批操作，重复投递因内容哈希与版本向量而幂等。批次按 500 条操作切分发布（接收端上限 5000）；同一设备自己发布的批次按文件名识别，不读取、不重放，只记为已处理，避免与本机状态打架。写入锁、锁的 owner 标记（`*.jsonl.lock.owner`）、bridge 和临时文件只属于本机进程：扫描不上传，发送端不再为状态里残留的这类记录发布删除；旧版本曾把每个打开的会话的 owner 标记（每 30 秒重写）都发布出去，云端因此可能有几千个只含这类记录的批次，接收端整条跳过，从不写入或删除它们。

### 对外接口

`service.ts` 的 `SyncService` 是 Web 层唯一入口：`status()`、`updateConfig()`、`connect()`、`disconnect()`、`runNow()`、`startManual("download" | "sync")`、`bindWorkspace()`、`start()`、`dispose()`。手动“立即下载 / 立即同步”由引擎的 `runManual()` 执行：等当前一轮结束后再跑，下载会反复列出批次直到没有新的，进度在状态的 `manual` 里；暂停时拒绝。自动轮次同样反复列出直到没有新批次，任何轮次正在搬运的数量都在状态的 `progress`（`{ stage, done, total, step? }`）里，最多每 250ms 推送一次；下载分两步：`read` 计读取云端变更清单的数量，`apply` 计下载并写入的记录数量。搬运过东西的轮次 1.5 秒后接着跑下一轮。下载一轮先弄清要改什么（新批次的清单 16 个并行读取，读失败的留到下一轮、不让整轮失败，未处理完的清单缓存在内存里不重复读；或读设备快照），再按记录分组、每条记录先试最新版本（覆盖旧版本的版本向量计数和一定更大），写下最新版后同一记录的旧版本都算已覆盖、不再下载；内容 16 个并行下载、内存预算 192 MB，写入仍逐条串行；下载前先把这一轮要下载的对象一起查好位置（`locateObjects`，每次查询 25 个名字、最多 4 个查询同时进行），下载时不再每个对象先单独查一次；一个批次的所有变更都有着落后才记为已处理。批次目录在启动、手动运行和每 30 分钟时完整列出，其余轮次只列出最新已见文件之后创建的（重叠 10 分钟）。Drive 限速（429，或 403 `userRateLimitExceeded`/`rateLimitExceeded`）指数退避重试最多 5 次，拒绝权限的 403 不重试。已处理批次按设备记水位（`appliedUpTo`，见 `foldAppliedBatches`），列表上限 50,000 条，每轮下载结束时折叠；应用某设备的快照后它的水位直接移到快照的 `upTo`。同步引擎本身可由测试直接构造：`new SyncEngine({ agentDir, dataRoot, deviceId, deviceName, store, accountKey })` 后 `setDrive()` + `runOnce()`。

### 依赖

- 依赖：`config/paths`、`config/web-prefs.ts`（常用提示词所在的 Web UI 偏好文件）、`data/workspace-store.ts`（工作区身份导入与绑定）、`session/mode-state.ts`（通用指令与草稿）、`session/memory/store.ts`（记忆锁、归档与索引）、`session/storage/jsonl`（会话头与条目解析）、`utils/atomic-write`、`utils/open-browser`。
- 被依赖：`modes/web/web-mode.ts`（创建服务、注册路由、关闭时释放）、`modes/web/routes-sync.ts`。
- 不依赖：Agent runtime、模型调用、工具执行。应用远端内容只写文件与状态，不触发模型、记忆提取或命令执行。

### 内置浏览器

种类 `browser` 的记录就是桌面端资料目录（`<agentDir>/desktop-profile`，Electron 的 userData）里的一个文件，原样上传、原样写回；桌面端 `packages/desktop/browser-sync.cjs` 监听该目录，文件被写入后对应存储重新读取。只认 `browser-data.ts` 白名单里的文件名，Chromium 自己的数据库、缓存和密码文件一律不扫描；引擎另开一个只看这些文件名的目录监听。两台电脑都改过同一个文件（包括首次连接前两边已有书签）时不进冲突列表，而是像记忆一样合并后再发布：书签按 id 合并、同一网址只留最早添加的一条、按添加时间排序；快捷方式保留一整套布局，把另一套独有的网址追加在后；缩放和深色按网站合并；网站权限任一边拒绝即拒绝；单个取值按固定规则选一个。合并结果与哪边是“本机”无关，所以两台电脑得到同一份文本、下一轮就收敛。浏览器文件从不因为另一台电脑删除而删除：收到删除时保留本机文件并重新发布，删除的那台会把文件拿回来。登录状态和密码只在加密包里，每台电脑只写自己的包，所以加密包之间不会并发冲突，也不需要（且无法）在这里合并；本目录看不到口令和明文。

## 维护

- 只同步数据含义，不整目录复制：新增数据类型时先判断它属于记忆、会话、文件、工作区、草稿还是指令，再改 `scope.ts` 的扫描与 `apply.ts` 的应用；不要并入“全部文件”。
- 编程模式聊天不上传；编程模式记忆通过记忆扫描上传。改动扫描门槛时必须保持这个边界。
- 删除必须是显式批次操作；墓碑永远保留“已删除”事实，旧设备重新上线不能把内容带回来。并发删除与编辑两侧都保留，不能静默丢一边。
- 冲突不阻塞同步：会话合并分支，其余类型保留本机版本 + 另一版副本 + 冲突列表。不要在“无法判断”时自动选一个版本删掉另一个。
- 云端对象先到、批次后到；缺对象的变更等待，同批其他记录照常按版本向量写入（每条记录各自收敛），批次要等全部变更都有着落才记为已处理，下一轮从缓存的清单重试。应用前校验 SHA-256。只有云端确实没有的内容计入延期次数（`MAX_DEFERRALS`），超过后在 `<agentDir>/sync/state-*.json` 的 `issues` 中报告并停止重试，不能无限循环；本机正在运行的会话和请求失败只等待、不计次数，不能因此跳过批次。损坏批次、超大文件、非法记录同理，一条坏数据不能拖住其他同步。
- Data root 若位于 Google Drive/OneDrive 等同步目录，引擎拒绝启动并提示迁移，避免双重管理。
- 工作区恢复只创建受管理占位目录并标记待绑定；不得因为远端记录里的绝对路径在本机存在就自动写进去。扫描以工作区注册表为准：被用户从所有列表移除的工作区不再上传，重新加入后才继续同步。
- OAuth 使用 `drive.file`（只能访问应用创建/用户明确交给应用的文件），不要升级为全盘权限；令牌只落本机 0600 文件，不能进入日志、聊天或同步内容。
- 账号切换按账号隔离协议状态；切换账号时清空 folder/sync 指针并要求重新连接。
- 一轮里下载失败不能挡住上传：`executePass` 先下载，失败也照常上传，再报告下载错误。应用远端内容时遇到磁盘满、文件占用、无权限（`LOCAL_ENVIRONMENT_CODES`）要停下并让批次留在待下载，不能记成 `apply-failed` 后标记已应用。
- 内置浏览器：新增可同步的浏览器文件时同时改 `browser-data.ts` 的白名单、它的合并函数和桌面端 `browser-sync.cjs` 的重新读取表；合并必须对称（交换两边结果逐字节相同），否则两台电脑会来回发布。登录状态和密码不得以明文进入任何记录。测试在 `test/google-drive-sync.test.ts` 的 “built-in browser” 与 “browser file merge”。
- 相关测试：`test/google-drive-sync-resume.test.ts`（中断续传、发布日志、离线计数、下载失败不挡上传、磁盘满、手动按钮）、`test/google-drive-sync.test.ts`（假 Drive、双设备恢复、分支合并、删除不复活、并发冲突保留、草稿与指令、缺对象延期、批次不重放、大变更集分批、自身批次忽略、非法身份拒绝、损坏批次与缺失对象上报、归档标记、移除工作区不再发布）与 `test/google-drive-sync-catchup.test.ts`（几千个锁标记批次与同一文件多个版本只下载最新版、本机锁不被碰、状态约每秒写一次；新电脑从快照追上、不读批次；快照缺大对象时等待再完成，一直不到就改读批次、只报告缺文件的那一批并可手动重试；运行中的会话不下载、不计延期；清单读失败不挡其他批次；增量列出与完整列出；两步进度；同内容新版本不下载；本机已有相同内容直接认领；Drive 客户端 403 限速重试、权限 403 不重试、合并查询、下载前批量查位置（最多 4 个查询同时进行，期间开始的下载不重复查询）与 `createdTime` 过滤）。
